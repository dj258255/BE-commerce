## 진행 상황

- **M0**: `docs/00-data.md`, `01-architecture.md`, `02-experiments.md`, `03-verification.md`,
  `04-storage.md` 작성. CI skip 게이트(#121)는 별도 PR로 완료.
- **M2 완료**: 온라인 컨텍스트 경로와 전달 방식 3종(`KAFKA`·`IN_PROCESS`·`IN_REQUEST`)을 세우고
  **E1을 측정했다** — [리포트](docs/runs/20260921-e1-신선도-지연/report.md). 무릎 50ms(반영률 7.3→100%,
  e2e p95 40ms), 컨슈머가 못 따라오면 대기가 무력, 인스턴스 2대에서 세 방식 모두 성립.
  **E2**(online/offline 일치율, #125)와 그 후속(E2-b 원자화 · E2-c 순서 관대 병합 · E2-e 잔여 축 ·
  E2-f 창 집계)까지 마쳤다. 기본 전달 방식은 네 번 뒤집혔고 지금은 **`IN_PROCESS`** 다 —
  매번 측정이 이유를 줬다([ADR-034](../docs/adr/ADR-034-personalization-context-deployment-unit.md) ·
  [ADR-035](../docs/adr/ADR-035-order-tolerant-context-merge.md) ·
  [ADR-036](../docs/adr/ADR-036-context-window-aggregate.md)).
- **M3 완료**: 추천 서빙(`recommendation` 모듈)과 과부하 정책 3종을 세우고 **E3을 측정했다** —
  [리포트](docs/runs/20260921-e3-과부하-degradation/report.md). **정책은 coverage를 사지 못하고
  (세 정책 차이 ±0.3%p) 지연을 산다**(같은 coverage에서 p95 160 / 320 / 454ms).
  기본값은 `ADMISSION`([ADR-037](../docs/adr/ADR-037-overload-admission-policy.md)).
- **M4 완료**: 제약 확인 시점 4종(확인 없음 / 생성 시작 / 생성 완료 후 / 응답 직전)을 정책으로 만들고
  **E4를 측정했다** — [리포트](docs/runs/20260921-e4-제약-재검증/report.md). 정책을 가른 것은 지연이
  아니라 **창**이다(생성 전 스냅샷 54ms = 모델 지연 vs 생성 후 확인 0ms). **응답 직전 확인은 생성 후
  확인과 위반율이 같았고 읽기만 한 번 더 썼다** — 마지막 확인을 늘려도 창은 사라지지 않는다.
  기본값은 `AFTER_GENERATION`([ADR-038](../docs/adr/ADR-038-constraint-revalidation-timing.md)).
  **후속(E4-b)까지 마쳤다** — [리포트](docs/runs/20260921-e4b-제약-재검증-실재고/report.md). 품절 집합
  크기를 6/24로 고정해 **위반율 순서를 정책 효과로 읽을 수 있게** 했고(통제 100%),
  제약 원천을 **실제 `stock` 테이블**로 바꿔 **확인 비용을 처음 쟀다** — 읽기 1회 ≈ 3~4ms,
  `AT_GENERATION_START`(미리 읽기)와 `AFTER_GENERATION`은 **비용이 같고 창만 다르다**(58ms vs 3ms).
  대가는 [ADR-039](../docs/adr/ADR-039-constraint-source-real-stock.md).
- **M5 완료**: 생성 범위 3종(전부 ranking / 앞부분 AR + Top-K / 전부 AR)을 정책으로 만들고
  **E5를 측정했다** — [리포트](docs/runs/20260921-e5-생성-범위-예산/report.md). 범위가 **모델 지연을
  정하고**(직렬 항목 수가 곧 비용), 그 지연이 **처리량을 판다** — 용량 **80 → 36 → 17/s**,
  도착률 고정 시 대가는 coverage 로(80req/s 에서 94.4% → 44.4% → 21.5%). 예산은 모델이 먹는다
  (모델 경로에서 추론이 **88.6~98.9%**). **품질(페이지 일관성)은 재지 않았으므로** 비싼 쪽을 켤 근거가
  없고, 기본값은 `RANKING` 이다([ADR-040](../docs/adr/ADR-040-generation-scope-and-budget.md)).
  **남은 것**: 일관성을 재는 방법 — 이게 생기면 앞부분 AR 의 최적 K 를 계산할 수 있다.
- **M6 완료**: 캐시 압축 임계값을 쟀다 — [리포트](docs/runs/20260921-e6-캐시-압축-임계값/report.md).
  교차점은 **187B(손해, 1.070)와 279B(이득, 0.817) 사이**로 관측됐고, **임계값은 1KB** 로 정했다
  (경계 근처의 이득은 몇 %라 값의 성질에 기댄다). 500KB 에서 저장량 **83% 감소**에 더해
  **get p99 가 2.02ms → 0.27ms(7.5배)** 로 내려간다. 코덱은 **`SNAPPY`** — 저장량은 LZ4 와 비슷한데
  CPU·지연이 낮았다(500KB 에서 242ms vs 359ms. **교과서 순서가 뒤집혔고 원인은 미확인**).
  **압축은 아직 켜지 않았다**: 컨텍스트 캐시는 Lua 가 값을 읽어 병합하므로 압축을 넣을 수 없다 —
  첫 적용 자리는 M7 의 홈 컴포저 결과 캐시다([ADR-041](../docs/adr/ADR-041-cache-compression-threshold.md)).
- **M1**: 수집·품질 리포트 완료(거래 31.8M, 2018-09-20~2020-09-22, 재구매 25.16%, 거래 없는 상품 995개).
  시간 스플릿(cutoff 2020-09-16) + point-in-time 피처 1,356,709행 + baseline MAP@12
  (repeat 0.0234 > popular_recent7d 0.0087 > popular_all 0.0029). 누출 회귀 테스트 통과.
  수치는 `docs/runs/`에 있다.
- **M8**: 화면 7종 + 홈 + 콘솔. **E1·E2·E3 화면은 실측으로 교체됐고**(`_mock` 없음), 나머지는 아직
  fixture(목)이며 화면이 스스로 목임을 밝힌다. 측정이 끝나면 같은 모양의 실데이터로 교체한다.
  **측정하지 않은 실험을 완료로 보이게 두지 않는다** — `experiments.json`의 `status`가 그 규칙을 지킨다.

  결정과 대가는 [ADR-032](../docs/adr/ADR-032-frontend-nextjs-adoption.md). 정적 프론트 제거는 남았다.
- **M11 진행**: 카테고리 2단계(#166)·패싯(#167)·위시리스트(#169, `wishlist` 모듈 + `V58`) 완료.
  남은 것은 리뷰·평점(#168)·이미지 전체 수집(#173)·검색 엔진 비교(#172).

## 하지 않은 것 (의도)

- **서비스 분리**: 경계가 측정으로 증명되기 전에는 쪼개지 않는다. 조건은 `01-architecture.md` §5.
- **모델 품질 최적화**: 모델은 교체 가능한 dependency다. 목표는 시스템 성질의 측정이다.
- **실사용자 지표**: 없는 것을 있는 척하지 않는다. 필요한 결정에서 경계를 남긴다.
