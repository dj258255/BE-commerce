# 03. 검증 기록 형식

> "테스트가 초록이다"는 검증이 아니다. **무엇을 실행했고 실제로 무엇이 나왔는지**를 남긴다.
> 실행하지 않은 것은 통과가 아니다 — 조건이 없어 건너뛴 테스트(skip)는 검증된 것이 아니다.

## 기록 형식

실험 하나가 끝나면 아래를 남긴다. 산출물은 `personalization/docs/runs/<날짜>-<실험>/report.md`에 둔다.

```markdown
# <실험 이름> — <날짜>

## 가설 (측정 전에 적는다)
무엇을 더 보장하면 무엇을 얼마나 지불할 것이라 예상했는가.

## 환경
장비(코어·메모리), 컨테이너 자원 제한, 도구 버전, 데이터 규모.
"로컬 단일 장비"라도 **그 사실을 적는다.**

## 부하 모델
동시 사용자/도착률, 요청 mix, 지속 시간, 워밍업, 표본 크기.

## 실행 명령
그대로 다시 돌릴 수 있게. 스크립트 경로와 인자까지.

## 실제 출력
원자료(요약 통계 + 표). 손으로 옮겨 적었다면 **옮겨 적었다고** 밝힌다.

## 판정
기준(가설) 대비 결과. 채택/기각/보류와 그 이유.

## 틀렸던 것
예상과 달랐던 지점. **재현되지 않은 가설도 여기 남긴다.**

## 남은 것
측정하지 못한 것, 시스템 지표로 판단할 수 없는 것(사용자 지표 필요), 다음 실험.
```

## 규칙

1. **수치에는 환경·부하·표본을 함께 적는다.** 없으면 재현할 수 없고, 재현 못 하는 수치는 근거가 아니다.
2. **skip을 통과로 세지 않는다.** CI는 실행하기로 한 테스트가 실제로 돌았는지까지 본다(건너뛴 게 있으면 실패).
3. **가설을 결과에 맞춰 고치지 않는다.** 틀린 가설은 "틀렸던 것" 절에 남긴다.
4. **합성 데이터를 쓴 실험은 그 사실을 결과에 적는다**(impression·재고 등).
5. **사용자 지표가 필요한 결정에서 멈춘다.** 시스템 지표로 대신 결론내지 않고 경계를 남긴다.
6. **재현 안 되는 결과는 결과가 아니다.** 최소 한 번 다시 돌려 같은 방향이 나오는지 본다.

## CI 게이트 (M0)

초록불을 그대로 믿지 않기 위한 장치다.

- CI가 **JUnit XML의 skipped 수**를 읽는다.
- 검증하기로 한 테스트가 하나라도 건너뛰어졌으면 **릴리스 실패**.
- 기준을 "테스트가 성공했는가"에서 **"검증하기로 한 테스트가 실제로 실행되고 성공했는가"**로 바꾼다.

구현 위치: `.github/workflows/ci.yml` (이슈 #121).
