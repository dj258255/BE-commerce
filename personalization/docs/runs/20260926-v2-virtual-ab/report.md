# D — 가상 사용자 A/B, v1 대 v2 (#305)

**A/A 는 통과했고, A/B 에서 v2 는 실제 구매 기준으로 v1 보다 페이지에 산 상품을 더 많이 담았다(적중 0.104 → 0.160, 차이 구간 [0.037, 0.075]).** 시뮬레이션 보상도 같은 방향이다(+0.76, [0.57, 0.97]). **시뮬레이션 클릭률만 반대 방향**이다(−0.004, [−0.009, −0.000]). 사전 판정대로 "이 시뮬레이터의 클릭률은 실제 구매와 정책을 거꾸로 가른다"고 적는다. C2(RL)의 보상으로 쓰기 전에 가중치를 다시 본다.

- 측정: 2026-09-26 15:27 ~ 15:51. v1 서빙 서버(`genpage_server.py`, final 모델)와 v2 서빙 서버(`genpage2_server.py`, `f-base-full-1ep`, final, CPU)를 HTTP 로 불렀다
- 방법 · 판정: `personalization/docs/genpage-v2/BACKEND.md` D 절(측정 전에 고정). 가상 사용자 · 반응 · 보상은 C0(#313)
- 재현:
  ```
  PY=<genpage 가상환경>/bin/python bash tools/run-v2-virtual-ab.sh
  ```
- 원자료: `aa/`, `ab/`(`result.json`, `report-table.md`), 서버 로그 `v1-server.log` · `v2-server.log`(오류 0)
- **이 비교로는 어떤 설정도 고르지 않았다.** 홀드아웃 주를 쓰지만 선택에 쓰지 않는다(ADR-054). v2 를 켜지 않는 결정(ADR-068)은 그대로다

  - v1: 구매 id 이력
  - v2: 시각 · 가격 · 채널이 붙은 이벤트, 프로필, 요청 시각, 다시 사기 행 고정(ADR-068 설정)

## 판정

1. **A/A 통과.** 네 지표의 차이 구간이 모두 0 을 포함했다. 배정과 하네스가 한쪽으로 기울지 않았다
2. **실제 구매 기준으로 v2 가 v1 보다 낫다(페이지 단위).** 홀드아웃의 페이지 적중률(v2 0.0691 · v1 0.0401, ADR-068)과 같은 방향이다. 앞 12개 순서로 매기는 MAP@12 에서는 v1 이 높았다(0.0209 대 0.0193). 두 결과가 다른 질문에 답하고 있다. v2 는 페이지 전체에 산 상품을 더 넓게 담고, 맨 앞 순서는 재구매 규칙을 못 이긴다
3. **시뮬레이터의 방향.** 페이지 보상은 실제 구매와 같은 방향이다. 구매율은 같은 방향이지만 구간이 0 을 걸친다. **클릭률은 반대 방향이다**(구간 끝이 0 에 닿는다). v2 는 실제 구매를 더 많이 담는데도 가상 사용자의 클릭은 약간 적었다. 원인은 확인하지 않았다. 사전 판정대로 **C2(RL)의 보상으로 쓰기 전에 반응 가중치를 다시 본다**

## 한계

- 반응 · 보상 가중치는 설정값이다. 실제 사용자의 클릭 · 구매 확률을 흉내 낸다는 주장이 아니다. 그래서 시뮬레이션 지표의 크기는 품질 주장으로 쓰지 않는다
- 행 제외(`exclude_categories`)는 v1 · v2 의 행 이름 체계가 달라 넣지 않았다. 2쪽에 같은 대분류 행이 다시 나올 수 있다
- 표본 5,000명, 요청 시각 하나(홀드아웃 주 시작)다
