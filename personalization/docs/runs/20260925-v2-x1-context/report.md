## 판정

1. **(e) 의 불일치 0 — 판정 기준 통과.** 서빙 서버는 학습 데이터를 만든 바로 그 함수(`dataset._context_from_arrays`)로 문맥을 만들고, 5,000명 전원에서 한 토큰도 다르지 않았다(`consistency_violation: false`)
2. **지금 앱이 주는 입력은 학습 때와 절반이 다르다.** 모델이 같아도 입력이 달라 **생성 페이지의 상위 12개 중 절반 이상이 바뀐다**(자카드 0.46)
3. **그런데 점수는 달라지지 않았다.** 다섯 수준의 MAP@12 차이는 표본 오차 안이다. B 의 결과(문맥을 더해도 손실이 줄지 않았다)와 같은 이야기다 — 이 모델은 시각 · 가격 · 프로필에서 점수를 얻지 못한다
4. **대가.** 학습과 같은 입력을 주려면 요청이 약 6배 커지고(595 → 3,825 B), 앱이 구매 시각 · 가격 · 프로필을 조회해야 한다. 그 대가로 사는 것은 "학습 때와 같은 출력"이고, 이 모델에서는 점수 이득이 측정되지 않는다

## 부수 발견

(c) · (d) 는 앱이 지금 보내는 이력 100개 전부에 시각 · 가격을 붙였고, (e) 는 모델이 쓰는 최근 60개만 보냈다. 그래서 정보가 더 많은 (e) 가 (d) 보다 작다. **모델이 쓰지 않는 61번째 이후 이벤트는 요청만 키운다** — 앱이 모델의 이력 길이(60)에 맞춰 잘라 보내면 된다.
