# T2 — 통계 곁채널로 격차를 83% 줄였지만 순차 모델은 여전히 졌다 (#447)

**곁채널을 단 순차 모델(G+F)도 순위 모델(R)에 졌다.** Taobao 광고 노출 데이터 시험 날(2017-05-13)에서 같은 초 묶음 안의 클릭 순서(묶음 GAUC)는 다음과 같았다.

- R(특징 + LightGBM) 0.5760
- G+F 0.5717

같은 고객 짝 부트스트랩(2,000회) 차이 구간은 **[−0.0061, −0.0026]** 으로 0 보다 아래다. 측정 전에 정한 판정 3 그대로 "졌다"로 적는다.

곁채널 자체의 효과는 컸다. 같은 순차 모델에 R 의 수치 특징 27개를 질의 곁채널로 넣자 묶음 GAUC 가 0.5512 에서 0.5717 로 올랐다(구간 [+0.0188, +0.0222]). R 과의 격차는 T1 의 0.0248 에서 0.0043 으로, 83% 줄었다.

- 설계 · 판정: `personalization/docs/genpage-v2/T2-TAOBAO-FEATURES.md`(측정 전에 고정)
- R 과 G 는 T1 의 시험 날 예측을 그대로 썼다(`personalization/docs/runs/20260930-t1-taobao/`)
- 측정: 2026-10-01 01:29 ~ 05:24
  - 회귀 확인(곁채널 없음 = T1): T1 체크포인트로 시험 날 5,000명을 다시 채점한 54,598행의 점수가 T1 예측과 같았다(최대 차 0)
  - G+F 학습 · 검증 3시간 48분, 최대 메모리 28.6GB(스왑이 차 T1 G 의 2시간 38분보다 느렸다), 시험 날 채점 5분
- 재현(`personalization` 에서, `TAOBAO_DATA` 는 원자료 위치):
  ```
  python -m taobao.run seq --split valid --config d128_l2 --side-features
  python -m taobao.run seq --split test --config d128_l2 --side-features --from-ckpt <cache/ckpt/d128_l2_side.pt>
  python -m taobao.run compare --a <R 시험 날 예측> --b <G+F 시험 날 예측> --out ...
  python -m taobao.run compare --a <G 시험 날 예측> --b <G+F 시험 날 예측> --out ...
  ```

## 무엇을 알게 됐나

1. **순차 모델이 진 가장 큰 이유는 통계를 못 받은 것이었다.** 같은 모델에 R 의 수치 특징만 더했더니 격차의 83% 가 사라졌다. T1 에서 추정한 원인이 측정으로 확인됐다
2. **그래도 트리를 넘지는 못했다.** 같은 수치를 받고도 묶음 안 순서에서 0.0043 뒤진다. 노출열을 읽는 부분이 트리 위에 더하는 정보는 이 데이터 · 이 규모에서 보이지 않았다
3. **보조 지표에서는 앞섰다.** 고객 GAUC 는 G+F 가 R 보다 0.0036 높았다(구간 0 위). 한 고객의 하루 전체를 줄 세울 때는 노출열이 도움이 된다는 뜻으로 보인다(추정). 측정 전에 정한 주 지표는 묶음 GAUC 라 판정은 바꾸지 않는다
4. **이력이 긴 고객에서 격차가 좁았다.** 노출열이 길수록 순차 모델의 몫이 커진다는 방향이다. 넷플릭스 · 쿠아이쇼우가 긴 이력을 쓴 것과 맞는다(추정, 구간은 따로 내지 않았다)
