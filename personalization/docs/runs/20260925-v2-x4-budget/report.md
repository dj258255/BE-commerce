## 판정

1. **예산 300 ms(앱의 모델 타임아웃) 안에 6행을 전부 한 칸씩 만들 수 없다**(p95 357 ms). 원문의 하이브리드(행마다 앞 2개만 한 칸씩)는 202 ms 로 들어온다. 3행이면 전부 한 칸씩도 196 ms 로 들어온다

3. **이 모델에서는 한 칸씩 생성한 시간이 점수로 돌아오지 않는다.** 세 방식의 MAP@12 가 같다. 비용 대비로는 순위만(113 ms)이 가장 싸다 — 다만 원문이 한 칸씩 생성하는 이유(앞 상품이 뒤 상품의 조건이 되는 페이지 단위 일관성)는 MAP@12 로 재지 않는다
4. **서버 처리량이 동시성과 무관하게 초당 약 14.5 페이지로 고정된다.** 모델 호출에 잠금 하나(v1 서버와 같은 구조)라 동시 요청은 줄을 서고 대기만 는다. v1 은 같은 `/page` prefix 2 에서 동시성 4 에 121/s · p95 42 ms 였다(#271). **v2 는 약 8배 무거운 의존성**이다 — X2 의 조건이 된다
