# 홈 다음 쪽의 GenPage 입력 (#270)

구매 이력을 쓰는 사용자의 홈 2쪽도 모델에 **구매만** 넣는다. 세션(1쪽 이후 본 것)을 넣던 지금보다 2쪽이 홀드아웃 주 구매를 약 19배
더 맞혔다(recall 0.0013 → 0.0251). 대가는 세션 반영이다. 2쪽 첫 행이 방금 본 대분류인 비율이 75% 에서 0% 가 된다. 세션을 구매 앞에 붙이는 절충(V2)은
두 기준을 모두 못 넘었다. 판정 기준은 [이슈 #270](https://github.com/dj258255/BE-commerce/issues/270)에 **측정 전에** 적었다.
결정은 [ADR-066](../../../../docs/adr/ADR-066-next-page-follows-purchase-history.md).

## 방법

- #254 와 같은 H&M 홀드아웃 표본(seed 7)의 앞 1,000명. 사용자마다 회원 가입 → 과거 구매 최근 100건을 그 회원의 결제 완료 주문으로 심는다(주문 14,792 · 항목 48,212)
- 사용자마다: 세션이 비었는지 확인 → 1쪽 → 2쪽(조회 전) → 2쪽 첫 행이 아닌 대분류의 상품 하나를 VIEW → 2쪽(조회 뒤)
- 조회한 상품은 대분류마다 하나(모델 어휘 안 · 재고 있음 · 가장 작은 id). 활동은 요청 안에서 반영(`IN_REQUEST`)
- 모델 서버 `genpage_server.py`(CPU 2스레드), 하이브리드 디코딩 `prefix=2`, 2쪽 3행 × 8개
- recall@2쪽 = 조회 뒤 2쪽 항목 중 홀드아웃 주(2020-09-16~22)에 산 상품 수 ÷ 그 주에 산 상품 수, 사용자 평균

| 변형 | 앱 설정 | 2쪽 모델 입력(최근 것부터) |
|---|---|---|
| V0 세션(지금) | `history-source=activity` | 최근 조회·클릭 |
| V1 구매 | `history-source=purchases` · `page-history=purchases` | 구매 최근 100건 |
| V2 세션 + 구매 | `history-source=purchases` · `page-history=session-then-purchases` | 조회·클릭, 그 뒤에 구매 |

## 결과

| 변형 | recall@2쪽 | 적중 사용자 | 세션 반영 | 모델 행 | 2쪽 p50 | 2쪽 p95 |
|---|---:|---:|---:|---:|---:|---:|
| V0 세션(지금) | 0.0013 | 0.5% | **75.0%** | 100% | 67ms | 79ms |
| V1 구매 | **0.0251** | 6.3% | 0.0% | 100% | 74ms | 86ms |
| V2 세션 + 구매 | 0.0191 | 4.6% | 12.8% | 100% | 71ms | 88ms |

배선(V1, 조회 전 2쪽을 엔진 `Engine.page` 를 같은 입력으로 직접 부른 값과 대조): 대분류 순서 1,000/1,000, 항목 1,000/1,000 일치.

### 판정

1. **배선 통과.** 순서·항목 모두 100%(기준 99%)
2. **지연 통과.** 세 변형 모두 2쪽 p95 300ms 이하
3. **V2 탈락.** recall 이 V1 의 0.76배(기준 0.95배 이상), 세션 반영이 V1 보다 12.8%p 높다(기준 20%p 이상). 둘 다 못 넘었다
4. **V1 채택.** recall 이 V0 보다 높다. `history-source=purchases` 일 때 2쪽 기본 입력은 구매다(`page-history=purchases`)
5. `history-source=activity`(전체 기본값)의 동작은 바뀌지 않는다

### 읽을 때

- V0 의 세션 반영 75% 는 조회 **한 건**만으로 만든 값이다. 모델이 그 한 토큰의 다음 분포를 대분류별로 합쳐 첫 행을 고른다
- V2 에서 세션 반영이 12.8% 에 그친 것은 조회 한 건이 구매 수십 건(중앙값 40건) 뒤에 붙어서다. 모델은 가장 최근 토큰만 보지 않는다
- V2 가 recall 을 잃은 이유는 학습에 없던 조회 토큰이 섞여서로 보지만 나눠 재지는 않았다
- 이 표본은 모두 과거 구매가 있는 사용자다. 구매가 없는 사용자는 V1 에서 빈 이력으로 생성한다(세션도 넣지 않는다). 재지 않았다

## 무효로 버린 두 실행

두 번 모두 하네스가 세션을 제대로 지우지 못했다. 숫자는 그럴듯하게 나왔다.

| 실행 | 무엇이 틀렸나 | 드러난 곳 |
|---|---|---|
| 1 | 세 변형이 같은 회원을 쓰는데 `user_activities` 를 지우지 않아, V1·V2 의 조회가 (user_id, seq) 중복으로 409 가 됐다 | V1·V2 의 조회 기록 성공률 0% |
| 2 | 세션 키를 `ctx:{id}` 로 지웠는데 실제 키는 `ctx:{id}:v2` 였고, 지운 곳도 도커 Redis 였다. 앱은 `localhost:6379` 에서 로컬 redis-server 에 붙는다 | V0 의 세션 반영이 0% — 조회 **전** 2쪽 첫 행이 이미 첫 실행 때 본 대분류였다 |

세 번째 실행부터 하네스가 사용자마다 시작 전에 세션이 비었는지 API 로 확인하고, 조회가 하나라도 기록되지 않으면 숫자를 내지 않고 멈춘다.
