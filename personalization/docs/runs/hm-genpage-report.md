# GenPage 최소형: 학습·채점·서빙 실측 (#238)

판정 기준은 [이슈 #238](https://github.com/dj258255/BE-commerce/issues/238)에 측정 전에 적었다. 결정은
[ADR-053](../../../docs/adr/ADR-053-genpage-mini-not-default.md).

## 무엇을 만들었나

| GenPage | 이번 |
|---|---|
| 이력을 토큰 시퀀스(프롬프트)로 | 구매 이력을 상품 토큰(어휘 82,759개 = train 에서 10번 이상 팔린 상품, 전체의 79.7%)으로 |
| 사전학습(다음 토큰 예측) | causal transformer 2층 · 2헤드 · 64차원, 파라미터 5.4M, 사용자 표본 40만 명 중 어휘 안 구매가 2개 이상인 361,133명, 최근 50개 |
| 후학습(가중 이진분류·강화학습) | **하지 않았다** — 노출·보상 로그가 없다 |
| 행 토큰 생성 | 학습하지 않았다. 다음 상품 분포를 대분류별로 합쳐 행을 고른다 |
| 생성 중 규칙 강제 | 이미 나온 상품·앞 쪽 상품·다른 대분류 상품을 매 단계 마스크 |
| 하이브리드 행 디코딩 | 행마다 앞 k 개만 한 칸씩, 나머지는 한 번에 |

학습·채점은 ALS(ADR-048)와 같은 하네스다 — `features_hm` 의 `split`(cutoff 2020-09-16, 홀드아웃 7일)·`map_at_k` 를 import 했다.
평가 고객 68,984명은 ALS·기준선과 같다.

## 채점

| 학습 | 바꾼 것 | 마지막 에폭 평균 손실 | MAP@12 | 이미 산 상품 제외 | 학습 시간(MPS) |
|---|---|---:|---:|---:|---:|
| 1차 | PyTorch 기본 초기화(표준편차 1), 2에폭 | 9.76 | 0.013379 | 0.001474 | 약 9분 |
| 2차 | 임베딩 초기화 표준편차 0.02 | 8.33 | 0.018519 | 0.007534 | 약 9분 |
| 3차 | 4에폭 | 7.71 | **0.020937** | 0.007758 | 약 17분 |

| 비교 | MAP@12 |
|---|---:|
| **선: 마지막 구매 재추천(측정 전에 고정)** | **0.023354** |
| GenPage 최소형(3차) | 0.020937 (선의 90%) |
| 최근 7일 인기 | 0.008748 |
| ALS 최고 구성(ADR-048) | 0.007608 |

- **선을 못 넘었다.** 3차가 선의 90% 다
- **ALS 의 2.8배다.** 같은 데이터·같은 채점기에서 순서를 보는 모델이 행렬 분해보다 훨씬 낫다
- **이미 산 상품을 빼면 63% 떨어진다**(0.020937 → 0.007758). 점수의 상당 부분이 재구매 흉내에서 온다. ALS(−46%)와 같은 모양이다
- 1차의 첫 손실이 16.8 로 균등 분포(ln 82,760 ≈ 11.3)보다 높게 시작했다. 가중치 공유 출력에 표준편차 1 짜리 임베딩을 쓰면 로짓이 너무 크다. 2차에서 고쳤다

### 왜 3차에서 멈췄나

에폭을 두 배로 늘려 +13% 를 얻었고 선까지 11.5% 가 남았다. 한 번 더 늘리면 넘을 수도 있다. 그런데 **같은 홀드아웃을 보고 세 번 골랐다.** 여기서 더 고쳐 선을 넘기면 모델이 나아졌다는 증거보다 홀드아웃에 맞춘 결과에 가깝다.
더 튜닝하려면 검증 기간(예: 홀드아웃 직전 1주)을 따로 떼고 거기서 고른 뒤 홀드아웃은 한 번만 보는 것이 먼저다.

## 서빙

2차 모델로 쟀다. 구조가 같아 3차 모델과 지연은 같다(가중치만 다르다). 모델 서버는 표준 라이브러리 HTTP 서버 + PyTorch CPU 2스레드.

### 모델 서버 직접 (합성 이력 200개, 3행 × 8개)

| 행 디코딩 | 순전파 | p95 동시성 1 | p95 동시성 4 | 규칙 위반 |
|---|---:|---:|---:|---:|
| 한 번에(k=0) | 3 | 9ms | 20ms | 0 |
| **하이브리드(k=2, 기본)** | 9 | 19ms | 29ms | 0 |
| 전부 한 칸씩(k=8) | 27 | 46ms | 64ms | 0 |
| 추천 행 `/recommend`(12개) | 1 | 3ms | — | — |

순전파 수가 곧 비용이다. 하이브리드는 행의 앞부분만 한 칸씩 사고 나머지를 한 번에 고른다 — GenPage 가 이 방식을 쓰는 이유가 순전파 수(9 대 27)로 보인다.

### 앱을 거쳐 홈 2쪽 (사용자 30명)

| 2쪽 행 | p95 | 행 전략 | 쪽 사이 중복 | 대분류 불일치(DB 대조) |
|---|---:|---|---:|---:|
| 규칙(대분류 인기, 지금 기본값) | 124ms | 세션 86 · 인기 4 | 0 | 0 / 720 |
| GenPage k=0 | 86ms | GENPAGE 90 | 0 | 0 / 685 |
| GenPage k=2 | 94ms | GENPAGE 90 | 0 | 0 / 685 |
| GenPage k=8 | 91ms | GENPAGE 90 | 0 | 0 / 685 |

- **서빙 기준(p95 300ms 이하) 충족.** 모델 행이 규칙 행보다 빠르다 — 규칙 행은 신상품 채우기 조회가 붙는다
- **규칙 위반 0.** 모델이 생성 중에 지킨 것(중복·대분류)을 앱이 DB 로 다시 대조했다
- 항목 685 대 720: 모델 행은 품절과 카탈로그에 없는 상품을 생성 뒤에 걸러 행당 평균 7.6개다
- 홈 p95 는 디코딩 방식에 거의 반응하지 않았다(86~94ms). 모델 시간(9~46ms)보다 나머지 경로가 크다

## 이 측정이 말하지 않는 것

- 후학습을 하지 않았다. GenPage 가 페이지 수준 보상으로 얻는 것(행 사이 상호작용, 다양성)은 이 모델에 없다
- 행 선택은 학습한 것이 아니라 상품 분포의 합이다
- 이력이 없는 신규 고객(홀드아웃의 8.1%)은 점수를 내지 못한다. 콘텐츠 임베딩은 넣지 않았다
- 서빙의 이력은 합성이다
