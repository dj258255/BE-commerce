# A/B 실험 기반: 합성 사용자로 끝에서 끝까지 (#256)

배정·노출 기록·귀속·분석이 끝에서 끝까지 맞게 돈다. 합성 사용자 1,000명에게서 고정 배정 위반 0, 비율 불일치 없음(SRM p 0.75 · 0.41),
A/A 에서 차이 없음, 일부러 넣은 차이는 95% 구간 안으로 복원, 노출되지 않은 상품의 클릭·구매는 하나도 세지 않았다. 판정 기준은
[이슈 #256](https://github.com/dj258255/BE-commerce/issues/256)에 측정 전에 적었다.

> **여기 숫자는 추천 품질에 대한 주장이 아니다.** 사용자 행동은 하네스가 정한 확률이다. 이 리포트는 실험 기반이 맞게 도는지만 말한다.
> 실사용자 A/B 는 트러블슈팅 기록의 열린 항목 5 로 남는다.

## 무엇을 만들었나

| 조각 | 무엇 | 어디 |
|---|---|---|
| 배정 | `SHA-256(솔트:사용자 id)` 의 앞 4바이트 mod 10,000 < 실험군 % × 100 이면 실험군. 저장하지 않는다 | `experiment/ExperimentAssigner` |
| 변형 | `rec-history` 실험: 실험군 = 구매 이력 + 재구매 우선(ADR-060), 대조군 = 지금 설정 | `RecommendationService` |
| 노출 | 홈 1쪽 응답과 `home_impressions` 에 `experiment` · `variant`(V68) | `HomeComposer`, `HomeImpression` |
| 귀속·분석 | 노출 뒤 30분 안 클릭, 24시간 안 구매를 **그 노출에 있던 상품만** 귀속. SRM χ², 두 비율 차이의 95% 구간과 p | `tools/ab_analysis.py` |

설정은 `app.experiments.rec-history.enabled`(기본 false) · `.salt` · `.treatment-percent`(기본 50). 새 실험은 새 솔트로 시작한다.

## 방법

- 합성 사용자 1,000명을 가입시키고, 사용자마다 홈 1쪽을 **세 번** 연다(고정 배정 확인)
- 변형별 확률로 노출된 상품 하나를 클릭하고(`CLICK` 활동), 노출된 상품 하나를 산다(주문 + 결제 승인, 가짜 PG)
- **음성 대조**: 변형과 무관하게 노출되지 않은 상품도 클릭(20%)·구매(3%)한다. 분석은 이것을 세면 안 된다
- 사용자가 실제로 한 일을 정답 파일로 남기고 분석 결과와 맞춘다
- A/A(솔트 `aa-1`): 클릭 20% · 20%, 구매 5% · 5%. 주입 A/B(솔트 `ab-1`): 클릭 20% → 30%, 구매 5% → 8%

## 결과

| 실행 | 사용자(대조/실험) | SRM p | 고정 배정 위반 | 클릭 사용자 차이 [95% 구간] · p | 주입 | 구매 사용자 차이 [95% 구간] · p | 주입 |
|---|---:|---:|---:|---|---:|---|---:|
| A/A | 505/495 | 0.752 | 0 | −0.002 [−0.051, +0.047] · 0.933 | 0 | −0.017 [−0.043, +0.009] · 0.192 | 0 |
| 주입 A/B | 513/487 | 0.411 | 0 | **+0.062 [+0.010, +0.115]** · 0.021 | +0.10 | **+0.033 [+0.005, +0.060]** · 0.019 | +0.03 |

| 실행 | 귀속 클릭 = 정답 | 귀속 구매 = 정답 | 세지 않은 것(음성 대조) |
|---|---|---|---|
| A/A | 195 = 195 | 45 = 45 | 클릭 216/216 · 구매 29/29 |
| 주입 A/B | 239 = 239 | 51 = 51 | 클릭 198/198 · 구매 33/33 |

- **기준 1(고정성)**: 3,000번 방문, 두 솔트에서 위반 0. SRM p > 0.01. 통과
- **기준 2(A/A)**: 두 차이의 구간이 모두 0 을 포함한다. 통과
- **기준 3(주입 복원)**: 두 구간이 주입값을 포함하고 부호가 맞다. 통과
- **기준 4(음성 대조)**: 귀속 수가 정답과 한 건도 다르지 않고, 노출되지 않은 상품의 클릭·구매는 모두 세지 않았다. 통과

**주입 +0.10 에 분석은 +0.062 를 냈다.** 분석이 틀린 것이 아니다. 정답 파일에서 실제로 클릭한 사용자는 대조 107/513(0.209)·실험 132/487(0.271)이고,
차이가 정확히 0.062 다. 확률 0.2 와 0.3 을 약 500명에게 굴리면 이만큼 흔들린다. 그래서 기준을 "주입값이 구간 안에 드는가"로 잡았다.
이 규모(변형당 500명)에서 클릭 10%p 는 겨우 잡히고, 구매 3%p 는 구간 폭(±2.8%p)과 비슷하다. 실사용자 A/B 의 표본을 정할 때 이 폭이 출발점이다.

## 한계

- 합성 행동이다. 추천이 바뀌어 클릭이 달라지는 경로는 없고, 변형이 확률을 정했다
- 귀속 창(30분·24시간)은 고른 값이다. 실사용자 데이터로 정해야 한다
- 노출은 홈 1쪽만 변형을 적는다. 2쪽부터의 클릭은 변형에 귀속되지 않는다(추천 행이 1쪽에만 있다)
- 합성 사용자가 산 상품만큼 재고가 줄었다(구매 약 130건)

## 재현

```bash
./gradlew -p commerce bootJar
bash tools/run-ab-e2e.sh      # 합성 사용자 가입 → A/A → 주입 A/B → 분석 → 표
```

앱은 실행마다 솔트를 바꿔 다시 띄운다. 각 실행은 약 42초(1,000명, 동시 8).
