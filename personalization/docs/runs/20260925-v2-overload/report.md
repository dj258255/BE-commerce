## 판정

1. **병목이 옮겨 왔다.** v1 에서는 모델(999/s)이 병목이 아니었고 앱이 먼저 포화했다. v2 는 초당 23건에서 포화한다. 모델이 request path 의 가장 좁은 곳이 됐다
2. **SLO 를 지키려면 개인화를 부하에 비례해 포기해야 한다.** C 를 넘는 부하에서 개인화 비율은 정책과 무관하게 거의 C ÷ 부하다(1.5배 → 70%, 2배 → 52%)
3. **입장 제한의 값은 지연이다.** 제한이 없으면 요청이 모델 앞에 줄을 섰다가 대기 한도(400 ms)를 넘긴 뒤에야 인기 상품으로 물러선다 — 결국 폴백을 받는데 576 ms 를 기다린다(SLO 위반). 입장 제한은 같은 개인화 비율에서 폴백을 **즉시** 줘 p95 를 243 ms 로 SLO 안에 둔다. v1 에서는 모델이 병목이 아니라 이 차이가 드러나지 않았다
4. 1배 부하에서 입장 제한 쪽 p95 가 121 ms 로 제한 없음(57 ms)보다 컸다. 거절은 0 이었으니 게이트의 추정 대기(관측 처리량 2초 창)가 요청을 늦춘 것은 아니고 모델 서버의 대기가 흔들린 것으로 보이지만 확인하지 않았다
