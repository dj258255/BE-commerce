# X6 — 2쪽 부하가 v2 `/page` 용량을 넘을 때 자리 공유가 1쪽 추천 행을 지키나 (#353)

**자리를 공유하지 않으면 2쪽 부하가 v2 용량(Cp)에 닿는 순간 모델 서버가 통째로 무너졌다.** 1쪽 추천 행은 모델 호출 181건이 전부 실패해 개인화 0% 가 됐고, 2쪽 모델 행도 0% 였다. 자리를 공유하면(지금 기본값, #271) 같은 부하에서 추천 행은 개인화 100% · p95 235 ~ 256 ms 로 SLO(300 ms) 안에 남았다. 2쪽은 용량만큼만 모델 행(81.5% · 50.9%)을 받고 나머지는 규칙 행으로 갔다. v1 에서 앱이 먼저 무너져 판정하지 못한 질문(#271 B)을 v2 에서 판정했다.

- 측정: 2026-09-26 11:03 ~ 11:10. v2 모델 서버(`b-base-full`, validate, CPU)와 앱 bootJar. 입장 제한 OBSERVED, 조건당 40초 · 워밍업 10초
- 방법 · 판정: `personalization/docs/genpage-v2/BACKEND.md` X6 절(측정 전에 고정)
- 재현:
  ```
  PY=<genpage 가상환경>/bin/python CKPT=<.../genpage2/validate/ckpt/b-base-full> bash tools/run-v2-page-overload.sh
  ```
- 원자료: `<자리>-page-<2쪽 부하>/raw/`. 큰 로그(`model-server.log`, 자리 없음 조건의 `app.log`)는 gzip 으로 압축했다
- 측정 환경: 다른 세션의 실험(#352)이 끝난 뒤 3분 연속 다른 앱이 없을 때 시작했다. 시작 시점 부하 평균은 10.5 로 조용한 상태가 아니었다

## 결과

추천 행 6/s(0.25C)는 모든 조건에서 고정이다. 2쪽 부하는 0.5 · 1.0 · 1.5 Cp(Cp 16.5/s, X2)로 올렸다.

- 모든 조건에서 k6 dropped 는 0 이고 앱은 무너지지 않았다(달성 부하 = 요청 부하)
- 자리 없음 · 16/s 와 25/s 에서 앱은 2쪽 생성 실패를 16/s 에서 617건, 25/s 에서 992건 기록했다(`GenPage 행 생성 실패 → 규칙 행으로 물러선다`). 모델 서버 로그에는 끊긴 연결(`BrokenPipeError`)이 2,922건 있다. 앱이 300 ms 에 포기한 요청을 모델 서버가 끝까지 계산했다는 뜻이다(#271 에서 본 것과 같은 모양)
- 2쪽 p95 가 자리 공유에서 244 ms 로 오히려 낮다. 자리가 없으면 기다리지 않고 규칙 행으로 가기 때문이다

## 판정

1. **자리 공유의 비용(0.5Cp): 있다.** 2쪽 모델 행 비율(100% 대 100%)과 2쪽 p95(1.0배)는 기준 안이지만 **추천 행 p95 가 76 → 94 ms 로 1.24배**라 기준(1.1배)을 넘었다. 조건마다 한 번 쟀고 부하 평균이 높은 상태였다. 이 차이가 자리 공유 때문인지 흔들림인지는 가르지 못했다. 두 값 모두 SLO(300 ms)의 3분의 1 아래다
2. **자리 공유의 이득(1.0 · 1.5 Cp): 판정 기준대로 "자리 공유가 1쪽을 지킨다".** 자리 공유는 추천 행 모델 실패 0 · p95 256 ms 이하로 두 조건을 다 지켰다. 자리 없음은 둘 다 어겼다(실패 181건 · 개인화 0%, p95 308 ms)
3. 무너짐의 모양은 v1(#271 B, 자리 없음 · 2쪽 121/s)과 같다. 파이썬 스레드 서버는 요청마다 스레드를 만들어 줄에 상한이 없다. 앱이 포기한 요청까지 계산하느라 잠금 하나를 나눠 쓰는 `/recommend` 까지 제한 시간을 넘긴다. v1 은 모델의 2쪽 용량(121/s)이 앱의 2쪽 한계(30 ~ 60/s)보다 커서 이 부하에 닿기 전에 앱이 먼저 무너졌다. v2 는 모델이 먼저 포화해 같은 일이 앱이 멀쩡한 부하에서 일어났다

## 결정

- **자리 공유(`page-capacity: shared`)를 기본으로 유지한다.** v1 에서는 앱이 먼저 무너져 근거가 "비용이 없다"뿐이었다. v2 에서 "없으면 모델 서버가 무너진다"는 근거가 더해졌다
- 0.5Cp 의 추천 행 p95 1.24배는 비용으로 적는다. 다시 잴 조건: 조용한 장비에서 반복 측정해 차이가 흔들림 밖이면, 2쪽에 자리를 따로 몇 개 떼어 주는 방식(분리된 자리)을 비교한다

## 한계

- 2쪽 부하는 계정 8개가 같은 커서를 반복한다(#271 과 같은 한계). 실제 사용자의 2쪽은 커서가 모두 다르다
