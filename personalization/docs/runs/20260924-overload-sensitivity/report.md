# 과부하 정책의 파라미터 민감도와 모델 용량을 잘못 알 때 (#264)

`ADMISSION` 의 p95 는 예산을 그대로 따라가고 coverage 는 예산과 무관했다. 그런데 게이트가 모델 지연을 절반으로 잘못 알면 예산 100ms 에서 p95 가
315ms 가 됐다. 최근 2초의 처리량으로 대기를 추정하게 바꾸자 193ms 로 돌아왔고, 제대로 알 때의 값도 거의 그대로였다. 판정 기준은
[이슈 #264](https://github.com/dj258255/BE-commerce/issues/264)에 **측정 전에** 적었다. 결정은 [ADR-065](../../../../docs/adr/ADR-065-admission-by-observed-throughput.md).

ADR-037 의 대가에 "정책 파라미터 민감도를 모른다"와 "`ADMISSION` 은 모델 용량을 안다고 가정한다"가 있었다. 코드를 보니 스텁 모델과 게이트가
**같은 설정(`model.latency-ms`)을 읽어서**, E3 에서 게이트는 늘 진짜 지연을 알았다. 그 가정은 시험된 적이 없었다.

## 환경

E3 와 같다: 모델 스텁 4동시 · 50ms(용량 80/s), 부하 160/s(2×) · 320/s(4×), 40초, 열린 루프(k6). 스텁의 실제 지연을 따로 주는 설정
(`app.recommendation.model.stub-latency-ms`)을 더해 게이트가 믿는 지연과 떼어 놓았다.

### A. 파라미터 민감도 — 예측과 비교

- **ADMISSION: 예측대로.** p95 ≈ 예산 + 60~80ms(111 · 168 · 281ms). coverage 는 예산과 무관(±0.1%p). 정책이 사는 것은 지연이지 개인화가 아니라는
  ADR-037 의 결론이 파라미터를 바꿔도 유지된다
- **BOUNDED 48: 예측이 틀렸다.** 상한 × 50ms / 4 + 50ms = 650ms 로 봤는데 461ms 에서 멈췄다. 모델 앞 대기 상한(`busy-timeout-ms` 400)에 먼저 걸려
  1,095건이 대기 초과로 빠졌다. **상한과 대기 상한이 서로 물려 있다** — 상한을 올려도 대기 상한 너머로는 지연이 늘지 않고 대기 초과가 는다
- **BOUNDED 12 는 ADMISSION 100 과 같은 값**이었다(168 · 164ms). 이 용량에서 상한 12 가 곧 대기 100ms 다. 용량이 바뀌면 이 대응도 바뀐다
- BOUNDED 24 의 2× 는 coverage 40.8%·p99 650ms 로 다른 조건과 결이 다르다. 대기 초과 41건이 섞였다. 한 번만 쟀다

### B. 용량을 잘못 알 때

게이트가 모델 지연을 50ms 로 믿고 실제는 100ms 면, 대기를 절반으로 계산해 줄을 두 배로 받는다. 예산 100ms 에 실제 지연 100ms 인데 p95 315ms —
판정선 (예산 + 실제 지연) × 1.5 = 300ms 를 넘었다. **ADMISSION 의 "예산으로 지연을 약속한다"는 장점이 용량을 알 때만 성립한다.**

### C. 관측 처리량으로 추정

게이트가 끝난 모델 호출을 100ms 칸 20개(2초)에 세고, 표본이 20건 이상이면 `대기 = 줄 길이 ÷ 처리량` 으로 추정한다. 호출 **시간**이 아니라 **끝나는 속도**를
쓴 이유: 호출 시간에는 모델 앞 대기가 섞여 있어 그것을 지연으로 쓰면 줄이 길수록 더 거절하는 되먹임이 생긴다.

- 용량 오판: 315 → **193ms**(판정선 240ms 이하). 통과
- 제대로 알 때: 168 · 164 → 153 · 153ms(−9% · −7%), coverage 44.5 · 22.6 → 44.7 · 22.7%(±10% 안). 통과

## 발견: ADR-037 의 기본값이 설정에 없었다

ADR-037 은 "기본 정책은 `ADMISSION`"이라고 적었는데 `application.yml` 과 코드의 기본값은 처음부터 `BOUNDED` 였다(기본값을 `ADMISSION` 으로
바꾼 커밋이 없다). 이번에 `ADMISSION` + 관측 추정으로 맞췄다.

## 한계

- 모델은 스텁(`Thread.sleep`)이다. 실제 모델의 지연 분포(꼬리)는 다를 수 있다
- 관측 창(2초)·최소 표본(20)은 고른 값이다. 용량이 갑자기 바뀌면 2초 동안은 옛 처리량으로 판단한다(재지 않았다)
- 각 조건 한 번씩
