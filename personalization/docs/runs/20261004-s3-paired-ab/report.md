# S3 — 짝 설계 가상 A/B 에서 결합 방식이 이겼다 (#462)

**같은 가상 사용자에게 두 줄 구성을 모두 보여 주자 결합 방식이 이겼다.** 홀드아웃 구매 고객 68,984명 전원에게 규칙 줄 구성(A)과 결합 방식(B, 순위 모델 점수 + GenPage 행 선택)을 차례로 보여 줬다.

- 실제 구매 적중(페이지에 그 주 실제로 산 상품이 있었는지): A 0.2252, B 0.2296, 차이 **+0.0044**, 95% 구간 **[+0.0030, +0.0058]**
- 앱이 상품 3개 미만 행을 버리는 규칙을 두 쪽에 똑같이 적용해도 +0.0051 [+0.0038, +0.0065] 로 같은 방향이다

측정 전에 정한 판정 1 에 따라 "짝 설계 가상 A/B 에서 결합 방식이 이겼다"로 적는다. 보조 지표가 같은 방향이라 판정 2 에 따라 ADR-068 의 다시 볼 조건 중 "가상 사용자 A/B" 를 충족한 것으로 적는다. 기본값을 실제로 켤지는 판정 3 대로 범수 님이 정한다.

- 설계 · 판정: `personalization/docs/genpage-v2/BACKEND.md` "S3" 절(측정 전에 고정)
- 측정: 2026-10-04 09:20 ~ 12:28(3시간 7분), 모델 서버 final `f-base-full-1ep` · CPU · 스레드 2, S1 L4 와 같은 서버 설정 · 요청 본문 · 2쪽 `exclude` · 이벤트 100건
- 재현:
  ```
  PY=<.venv-genpage>/bin/python bash tools/run-s3.sh
  ```
- 원자료: `result.json` · `report-table.md` · `paired.txt` · `server.log`. 고객별 값(68,984행)은 저장소 밖 `personalization/data/hm/runs-s3-paired-ab/paired-customers.parquet` 에 남겼다

## 설계

- 배정 없이 사용자마다 두 정책을 모두 돌렸다. 반응 난수는 고객 · 날짜로 정해지는 시뮬레이터 그대로라 두 정책이 같은 난수를 쓴다. 차이는 정책에서만 생긴다
- 사용자 단위 짝 부트스트랩 2,000회(시드 7)
- 요청 실패 0, 실패로 뺀 사용자 0. 응답 집계는 A `rule` 92,425건 · B `hybrid` 91,618건, 대체 0

- 페이지 보상 합(시뮬레이터)은 결합 방식이 높았다

## S1 과 무엇이 달랐나

| | S1 L4(비대응) | S3(짝) |
|---|---|---|
| 사용자 | 5,000명을 둘로 나눔(약 2,500 · 2,500) | 68,984명 모두 두 정책 |
| 실제 구매 적중 차이 | +0.0118 | +0.0044 |

S1 의 차이 +0.0118 은 서로 다른 사용자 무리를 비교한 값이라 무리 사이의 우연이 섞였다. 같은 사용자의 차이로 재자 구간이 16분의 1 로 줄었고, 차이의 크기는 D5 오프라인(페이지 적중 +0.003)과 같은 자릿수로 돌아왔다.

## 남은 한계

- 가상 사용자 시뮬레이션이다. 실제 구매 적중은 "그 주에 실제로 산 상품이 페이지에 있었는지"라 실제 데이터에 기대지만, 보여 줬다면 샀을지는 알 수 없다
- 앱 홈은 1쪽이 추천 행 · 규칙 행이고 GenPage 는 2쪽(3행)만 만든다. 이 비교는 S1 과 같이 6행 페이지 두 쪽을 GenPage 로 만든 설정이다. 앱 2쪽 그대로의 구성은 S2 에서 지연 · 대체 경로만 쟀다
