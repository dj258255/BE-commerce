재구매 차이는 validate 에서 −0.000085, final 에서 +0.000092 로 방향은 다르고 크기는 비슷하다. 같은 날 산 상품의 순서 처리 차이로 보이지만 확인하지 않았다. 판정 선은 v1 기록값 **0.023354 를 그대로 쓴다**(v2 하네스 값 0.023446 이 더 높으므로 선을 넘었다고 말하려면 둘 다 넘어야 한다).

생성: validate 274초 · 최대 메모리 9.2GB, final 417초 · 9.2GB(`/usr/bin/time -l`). 학습 예시 validate 600,779 · final 595,707(상한 200만 미만). 정답 페이지 행 수 중앙값 2 · p90 4, 상품 수 중앙값 2 · p90 7.

**실측에서 드러난 결함 두 개** (단위 테스트는 통과했다)
- 통계 계산이 58분째 끝나지 않았다. `np.int32 in range` 는 파이썬 int 가 아니라 빠른 경로를 못 타고 원소를 하나씩 비교한다(1회 3.7ms, int 는 0.4µs). 200만 예시에서 수십 시간이 된다
- 학습 첫 단계에서 죽었다. 학습 루프가 넘긴 상품 구간 끝(`item_end`)을 손실 함수가 대체 토큰 함수에 넘기지 않았다. 테스트는 다른 인자 모양으로 불러 이 경로를 안 탔다. 학습 루프 전체를 타는 테스트를 더하게 했다
