## T3 GenPage 행 선택에 순위 통계를 학습해 붙인다 (측정 전에 적는다, 2026-10-04, #463)

**왜.** D5 에서 이긴 결합(H'(4))은 GenPage 행 로그 확률에 순위 모델 행 점수 z 를 손으로 고른 λ=4 배로 더했다. T2(#447)에서는 순차 모델이 순위 모델의 통계를 곁채널로 받자 격차가 83% 줄었다. GenPage 가 행 통계를 직접 받아 행을 고르는 법을 학습하면 손으로 고른 λ 보다 나은지 묻는다.

**공통.** D5 와 같다. 순위 모델 R 점수 상위 200개, 6행, 행 = 섹션 행 + 다시 사기 행, 허용 행 = 상위 200개에 1개 이상(규칙 줄 구성과 같다), 행 안 = 점수 순 최대 8개(모델이 채우지 않음). GenPage 체크포인트는 검증 `b-base-full` · 홀드아웃 `f-base-full-1ep`, 두 체크포인트 모두 고정한다(학습하지 않는다).

**곁채널(T3 머리).**
- 행 특징(허용 행마다): 그 행 상위 8개 R 점수의 합 · 최댓값 · 평균, 그 행에 든 상위 200개 상품 수, 다시 사기 행 여부, 고객 안에서 행 점수 합의 순위. 점수 특징은 고객의 허용 행 안에서 표준화한다
- 머리: 작은 MLP(특징 → 16 → 1)의 출력을 GenPage 행 로그 확률(허용 행 안 log_softmax)에 더해 고른다. λ 는 두지 않는다
- 학습 데이터: 요청 시각 r − 7(검증) · 홀드아웃 요청 r − 7 주의 구매 고객 최대 10만 명(시드 7). 정답은 GenPage 사전학습과 같은 방식으로 다음 주 구매를 행으로 묶은 페이지의 행 순서를 허용 행으로 제한한 것
- **누설 방지:** 학습 주의 R 점수는 그 주의 정답을 보지 않은 순위 모델로 만든다. D2 설정 그대로 r − 14 · r − 21 두 주로만 학습한 모델로 r − 7 주 고객의 후보에 점수를 매긴다. 검증 · 홀드아웃의 점수는 D3 의 점수 파일(세 주로 학습한 R)을 그대로 쓴다
- 손실: 행 단계마다 허용 행 위의 교차 엔트로피(teacher forcing). AdamW lr 1e-3, 최대 5 에폭, r − 7 주의 10% 를 떼어 조기 종료, 시드 7
- **측정 전 보정(2026-10-04 09:40, 구현 검토 중):** 위 "D2 설정 그대로 r − 14 · r − 21 두 주로만 학습"을 조기 종료까지 맞춘다. D2 절차를 한 주 앞으로 밀어 r − 21 로 학습하고 r − 14 로 조기 종료해 반복 수를 정한 뒤 그 수로 r − 14 · r − 21 을 합쳐 다시 학습한다. 처음 구현은 조기 종료 없이 최대 1,000 번을 돌아 평가에 쓰는 순위 모델(약 240 번)과 점수 분포가 달라질 수 있었다. r − 7 은 학습 · 조기 종료 어디에도 쓰지 않는다

**판정.**
1. 검증 주 1만 명(D2 · D3 · D5 와 같은 표본)에서 T3 페이지 nDCG 를 잰다. 비교: H'(4) 0.0542, 규칙 줄 구성 0.0529(D5 검증)
2. T3 가 H'(4) 보다 0.0005 이상 높으면 홀드아웃 68,984명에서 한 번 재고, 같은 고객 짝 부트스트랩으로 T3 − H'(4) · T3 − 규칙 줄 구성의 구간을 낸다. 0 보다 위면 "학습한 머리가 손으로 고른 λ 를 이겼다" · "규칙을 이겼다"
3. 1 에서 0.0005 이상 높지 않으면 홀드아웃을 재지 않고 "학습한 머리가 손으로 고른 λ 를 넘지 못했다"로 적는다
4. 결과가 어느 쪽이든 그대로 적는다

## D5 행 규칙을 B 와 같게 (측정 전에 적는다, 2026-10-01, #450)

**왜.** D3 · D4 의 G 쪽은 "상위 200개에 8개 이상인 행만 허용" 규칙이 걸렸고 B 에는 걸리지 않았다. 검증 1만 명에서 다시 사기 행을 놓을 수 있는 고객이 G 쪽 1,759명, B 페이지에 다시 사기 행이 있는 고객 7,391명이었다. D5 는 이 규칙만 B 와 같게 풀고 다시 잰다. **묻는 것: 규칙을 같게 하면 GenPage 의 행 선택이 B 를 이기는가.**

**공통.** D3 와 같다(순위 모델 R 점수 상위 200개, 6행, 한 상품은 한 번, 행 = 섹션 행 + 다시 사기 행, D3 의 R 점수 파일, 검증 `b-base-full` · 홀드아웃 `f-base-full-1ep`). 바뀌는 것은 둘이다.
- 허용 행 = 상위 200개에 상품이 **1개 이상** 있는 행(B 가 고를 수 있는 행과 같다)
- 행 안 = 그 행의 상위 200개 상품을 R 점수 순으로 최대 8개. 모자라면 **짧은 행으로 둔다**(모델이 채우지 않는다). B 의 행 안과 같다

**변형.**

- H'(4): 행 로그 확률에 4 × z(행 점수)를 더해 고른다. λ 는 D4 검증에서 고른 4 를 그대로 쓰고 새로 고르지 않는다

   - 0 보다 위: **"규칙을 같게 하면 GenPage 행 선택이 이겼다"**

## D2 GenPage 대 업계 표준(후보 + 순위 모델) (측정 전에 적는다, 2026-09-28, #413)

**목표.** 넷플릭스가 보인 결과처럼, 같은 데이터 · 같은 평가에서 GenPage 가 업계 표준 추천보다 높은지. 업계 표준은 "여러 출처에서 후보 → 특징 → 순위 학습"이고, 이 H&M 데이터 공개 대회 상위 풀이도 이 형태였다. **순위 모델을 약하게 만들면 비교가 무의미하다.** 그래서 후보 · 특징 · 설정을 여기서 먼저 고정하고 GenPage 쪽과 같은 튜닝 기회만 준다.

**R: 후보 + 순위 모델.** 요청 시각 r 이전 데이터만 쓴다.
- 후보(고객마다, 합집합)
  - C1 재구매: r 전 4주 동안 그 고객이 산 상품
  - C2 전체 인기: r 전 7일 판매 상위 100
  - C3 섹션 인기: 고객 이력 섹션마다 r 전 7일 상위 20
  - C4 비슷한 상품: 최근 산 5개 각각과 의미 임베딩(e5)이 가장 가까운 20개
  - C5 같이 산 상품: r 전 4주에 고객이 산 상품마다, 같은 고객 · 같은 날 함께 산 상품 상위 10
- 특징
  - 출처 표시 5개
  - 고객 × 상품: 산 횟수(전체 · 4주), 마지막으로 산 뒤 지난 일수
  - 상품: 판매량(1 · 7 · 28일), 7일/28일 추세, 가격 중앙값, 섹션, 첫 판매 뒤 일수
  - 고객: 나이, 구매 수(전체 · 4주), 마지막 구매 뒤 일수, 평균 가격
  - 교차: 가격 비(상품 / 고객 평균), 고객 구매 중 그 섹션 비율, 최근 5개와의 최대 e5 코사인

- 모델: LightGBM LambdaRank(질의 = 고객). num_leaves 63, learning_rate 0.05, 최대 1,000 반복, min_child_samples 50, feature_fraction 0.8, bagging_fraction 0.8
- 출력: 점수 순 상위 48개(앞 12개로 MAP@12, 48개로 페이지 적중)

**G: GenPage 도전.** 같은 후보 풀 위에서 생성한다(넷플릭스도 운영 후보 위에서 생성했다).

## C5 종합몰식 구성 (측정 전에 적는다, 2026-09-27, #382)

**왜.** 종합몰(쿠팡 · G마켓) 추천의 일반 구조는 "여러 출처에서 후보 뽑기 → 모델로 순위 · 페이지 구성 → 규칙으로 다시 정리"다. v2 는 모델이 페이지를 통째로 만들고, 앞 12개 순서에서 재구매 규칙에 졌다(홀드아웃 0.019268 대 0.023354). 그런데 H&M 홀드아웃 주에서 재구매는 드물다: 산 (고객, 상품) 쌍의 **2.9%** 만 전에 산 상품이고(절반은 7일 안), 전에 산 상품을 또 산 고객은 **7.1%** 다(2026-09-27 측정). 재구매 행은 소수에게 확실히 맞히는 자리이고, 나머지는 새 상품을 찾는 자리다. 둘을 역할대로 나눈다.

**변형.** 모두 디코딩 단계만 바꾼다(재학습 없음). 체크포인트는 검증 모드 `b-base-full`, 평가는 이제까지와 같은 검증 주 1만 명 표본이다.

| 변형 | 바꾸는 것 |
|---|---|
| M1 규칙 순서 재구매 행 | 첫 행 = 다시 사기 행. 그 안의 상품을 **모델이 아니라 최근 산 순서**로 채운다(이력에서 어휘에 있는 상품, 중복 없이 최대 8개. 모자라면 지금처럼 모델이 이력 안에서 채운다). 나머지 행은 모델 |
| M2 M1 + 비슷한 상품 후보 | 모델 행은 후보 집합 안에서만 생성한다. 후보 = 기존 운영 후보(지난주 인기 200 ∪ 이력 섹션별 인기 20) ∪ **최근 산 5개 상품 각각과 의미 임베딩(e5) 코사인이 가장 가까운 20개**(요청 전 어휘 상품만) |
| M3 M2 + 재구매 성향 배치 | 이력 안에 같은 상품을 두 번 이상 산 기록이 있는 사용자만 다시 사기 행을 첫 행에 둔다. 없는 사용자는 모델 행 두 개 뒤(셋째 행)에 둔다 |

**지표.** MAP@12(선), 페이지 적중(recall), 그리고 새 보조 지표 둘을 더한다. 이 둘은 측정 전에 여기서 정한다.
- **새 상품 적중**: 요청 뒤 7일 구매 중 이력에 없던 상품만 정답으로 본 페이지 recall. 재구매 규칙은 구조상 0 이다
- **재구매 적중**: 이력에 있던 상품만 정답으로 본 페이지 recall

**판정.**
1. M1 ~ M3 중 MAP@12 가 가장 높은 것을 고른다(차이 0.001 안이면 단순한 쪽. 순서 M1 < M2 < M3)
2. 고른 것이 표본 선 **0.02346** 을 넘으면 final 체크포인트(`f-base-full-1ep`)로 **홀드아웃을 한 번 더 본다**(홀드아웃 두 번째. 디코딩만 바꾸므로 재학습은 없다). 넘지 못하면 홀드아웃은 보지 않는다
3. 선을 넘든 못 넘든 새 상품 적중을 base + 고정 · 재구매 규칙과 나란히 적는다. "모델이 규칙 위에 무엇을 더하는가"는 이 숫자로 답한다
4. 평가는 조각 2개씩 돌린다(조각 하나 약 9.7GB, 2026-09-27 측정)
5. **(구현 검토 뒤 추가, 측정 전)** 구현 중 배치 디코딩의 캐시 결함 셋(길이가 다른 조각 붙이기 · 고정 뒤 접두 수 · bulk 이중 입력)을 고쳤다. 기본 경로가 바뀌지 않았는지 보려고 **M0 = base + 고정(기존 설정)을 같은 표본에서 다시 잰다.** 이전 값 0.01865 와 0.0005 넘게 다르면 M1 ~ M3 을 판정하지 않고 원인을 먼저 본다
