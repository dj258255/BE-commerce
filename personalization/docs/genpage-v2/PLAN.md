# GenPage v2 — Netflix GenPage 를 최대한 그대로 옮긴다

- 시작: 2026-09-25
- 상태: 진행 상황은 [STATUS.md](STATUS.md), 인터페이스는 [DESIGN.md](DESIGN.md)
- 원문: [GenPage: Towards End-to-End Generative Homepage Construction at Netflix](https://netflixtechblog.com/genpage-towards-end-to-end-generative-homepage-construction-at-netflix-77146fba8a08) (2026-06-29)

## 목표

v1(ADR-053)은 상품 토큰만 있는 2층 모델(파라미터 약 540만)을 다음 구매 예측으로만 학습했다. 서빙 구조(제약 디코딩 · 하이브리드 행 디코딩 · 쪽 나누기)는 원문을 따랐지만 학습은 가장 작은 형태였고, 측정 전에 정한 선(마지막 구매 재추천 MAP@12 0.0234)을 넘지 못했다(0.0209).

v2 는 원문의 구성 요소를 **데이터가 허락하는 데까지 전부** 옮긴다. 그리고 원문의 두 오프라인 발견을 이 데이터에서 다시 잰다.

1. 프롬프트를 풍부하게 하는 것이 모델을 키우는 것보다 효과가 큰가
2. RL 후학습이 목표에 없던 다양성을 늘리는가

| 하이브리드 행 디코딩 | 행마다 앞 k 개 한 칸씩, 나머지 한 번에 | 같음 |

## 똑같이 할 수 없는 것 (처음부터 적어 둔다)

1. **노출 로그가 없다.** 원문의 사전학습 데이터는 "서비스에서 긍정 반응을 받은 페이지"다. H&M 에는 구매만 있다. 정답 페이지로 대신하므로 v2 가 배우는 것은 "다음 주에 살 것을 행으로 묶기"다
2. **보상 시스템이 없다.** 원문은 A/B 로 다듬은 만족도 점수를 쓴다. v2 의 보상은 "다음 7일에 샀는가"다
3. **조회 · 클릭 행동이 학습 데이터에 없다.** 행동 종류 토큰(조회 · 클릭)은 어휘에 두지만 학습되지 않는다. 앱의 세션 행동은 서빙에서 넣되 한계로 적는다
4. **규모.** 원문 2억~9억 파라미터, 이 노트북(M2 Pro 32GB, MPS)은 수천만이 현실적이다

## 판정 기준 (측정 전에 적는다)

평가 기간은 v1 과 같다. 튜닝은 검증 주(2020-09-09 ~ 15)로만 하고, 홀드아웃 주(2020-09-16 ~ 22)는 묶음마다 마지막에 한 번 본다(ADR-054 와 같은 원칙).

| 지표 | 정의 | 비교 대상 |
|---|---|---|
| MAP@12 | 생성된 페이지를 배치 순서로 편 앞 12개, v1 과 같은 채점 함수 | 선 0.0234(마지막 구매 재추천) · v1 0.0209 |
| 페이지 recall | 페이지 전체(최대 6행 × 8개) 중 홀드아웃 주에 산 상품 수 ÷ 산 상품 수 | 사전학습 대 WBC 대 RL |
| 행 recall | 산 상품의 섹션이 페이지의 행으로 나온 비율 | 같음 |
| 다양성 | 페이지 안 상품 쌍의 콘텐츠 임베딩 평균 거리(원문과 같은 정의) | RL 전후 |
| 규칙 위반 | 행 중복 · 행 밖 상품 · 페이지 안 중복 · 앞 쪽 상품 재등장 | 0 이어야 한다 |
| 서빙 | 앱 경로 점수 = 엔진 직접 점수, 2쪽 p95(앱이 버티는 부하) | v1 서빙 |

채택: v2 가 홀드아웃 MAP@12 에서 **선(0.0234)을 넘으면** GenPage 기본 모델 후보로 올린다(기본값 켜기는 A/B 뒤). 넘지 못하면 무엇이 모자랐는지(데이터 · 크기 · 후학습)를 절제 결과로 적는다.

원문 발견의 재현(결과가 어느 쪽이든 적는다):

- **프롬프트 대 크기**: 같은 학습 예산에서 (a) 상품 이력만 · 작은 모델, (b) 문맥 전부 · 작은 모델, (c) 상품 이력만 · 큰 모델의 검증 손실과 MAP@12
- **RL 과 다양성**: RL 단계마다 보상과 다양성

## B 실행 계획 (측정 전에 적는다, 2026-09-25 · 06:00 원문 대조로 고침)

원문 대조([AUDIT.md](AUDIT.md))에서 처음 계획이 원문 실험과 달랐다. 원문은 **문맥을 고정하고 크기만 바꾸는 스윕**과 **크기를 고정하고 데이터 원천을 하나씩 더하는 누적 스윕**을 따로 했다. 처음 계획은 "이력만" 문맥에서 크기를 바꿨다. 결과를 보기 전에 원문 설계로 바꾼다.

**공통.** validate 데이터, 4,500단계(1에폭), 배치 128, 학습률 3e-4, 워밍업 500, 코사인, 대체 토큰 5%(상품 · 행), 시드 7, 1,000단계마다 eval.npz 앞 5,000개 페이지 손실. 한 번에 하나(MPS).

**문맥 스윕(small 고정, 원문 그림 6).** 이벤트 4토큰 `[상품][채널][며칠 전][가격]` 기준으로 원천을 하나씩 더한다.

| 점 | 문맥 수준 | 더한 것 |
|---|---|---|
| C1 | `items` | 구매한 상품만 |
| C2 | `+action` | 채널(매장 · 온라인) |
| C3 | `+time` | 며칠 전 |
| C4 | `+price` | 가격 구간(원문의 참여 크기 자리) |
| C5 | `+profile` | 나이 · 회원 · 뉴스 · FN · 활성 |
| C6 | `full` | 요일 · 월 |

**크기 스윕(전체 문맥 고정, 원문 그림 5).** small(C6 과 같은 실행) · base · large.

**지표.** 주 지표는 원문과 같은 **손실**(eval.npz 5,000개 페이지 토큰 손실, 학습 끝). 같이: 검증 주 전체 평가 고객 MAP@12 · 페이지 recall · 행 recall · 다양성 · 규칙 위반.

**원문 발견 1 판정.** 문맥 누적 효과 = 손실(C1) − 손실(C6), 크기 효과 = 손실(small) − 손실(large). 원문은 앞의 것이 약 6.9%, 뒤의 것이 약 1.3%(7.5배 크기)였다. 상대 감소율로 비교해 앞의 것이 크면 "재현", 작으면 "재현 안 됨"으로 적는다. MAP@12 로도 같은 비교를 적되 판정은 손실로 한다(원문이 손실로 판정했다).

**선택과 홀드아웃.** 검증 MAP@12 가 가장 높은 실행의 설정 하나를 고른다. 그 설정으로 final 데이터에서 다시 학습하고 홀드아웃 주를 **한 번** 본다. 선(0.023354)을 못 넘어도 다시 고르지 않는다(ADR-054 원칙).

## 선을 넘기 위한 순서 (측정 전에 적는다, 2026-09-25 07:00)

**방향 조정.** 이 프로젝트의 본래 목적은 모델 연구가 아니라 "모델이 request path 에 들어왔을 때 백엔드가 무엇을 보장하는가"다(최신성 · 과부하 · 결과 검증 · 지연 예산). 다만 모델이 단순 규칙(마지막 구매 재추천, 선 0.023354)보다 못하면 "그 모델을 왜 request path 에 넣나"에 답할 수 없다. 그래서 ML 은 **선을 넘는 데 필요한 만큼만** 하고 백엔드 실험으로 넘어간다. RL · 증분 학습 · 외부 데이터(RL4RS) · 오프라인 가상 사용자 기록은 선을 넘는 데 필요하지 않으면 하지 않는다.

**참고 수치.** 같은 데이터의 캐글 대회 상위권은 MAP@12 약 0.036 이었다(피처 · 후보 · 순위 모델 조합). v1 은 모델 단독 0.020930, "재구매 먼저 + 빈칸은 모델" 0.023779(ADR-054, 참고로만 잰 값).

**순서(싼 것부터, 앞에서 넘으면 멈춘다).** 전부 검증 주 MAP@12 로만 고른다. 최종 주는 마지막에 고른 설정 하나로 **한 번** 본다.

| 순서 | 방법 | 원문 근거 |
|---|---|---|
| 1 | B 비교 실행 8개 중 검증 MAP@12 최고 | 사전학습 |
| 2 | 1의 모델 + `ROW_REPEAT` 를 첫 행에 고정(`pinned={0: ROW_REPEAT}`, 이력 어휘 상품이 3개 미만이면 고정 없음) | 행 고정(pinning) |
| 3 | 2 + 후보 집합 안에서만 생성: 재구매(이력) ∪ 지난 7일 인기 상위 N ∪ 이력 섹션별 지난 7일 인기 상위 M. N · M 은 {(200, 20), (500, 50)} 두 점만 | "기존 운영 후보 집합 위에서 디코딩"(온라인 A/B) |
| 4 | WBC 후학습 1회: 사전학습 모델이 만든 학습 기간 페이지를 노출로, **실제 다음 7일 구매**를 라벨로(가상 사용자 반응이 아니라 실제 구매) | WBC |
