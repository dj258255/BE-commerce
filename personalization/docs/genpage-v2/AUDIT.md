# 원문 대조 감사 (2026-09-25 06:00)

B 학습(수 시간)을 돌리기 전에 원문을 문단 단위로 다시 읽고 구현과 맞췄다. 원문은 Chrome 으로 직접 열어 읽었다(자동 수집은 403). **이 감사는 B 비교 결과를 하나도 보기 전에 했다.** 지금까지 본 것은 스모크(2,000단계) 손실과 경로 확인용 5,000명 점수뿐이다.

판정: ✅ 원문과 같음 · 🔶 데이터 때문에 바꿔 옮김(이유 적음) · ❌ 빠져 있었음 → 아래 "고친다"

## 데이터 · 토큰

| 원문 | 구현 | 판정 |
|---|---|---|
| 학습 예시 = 노출 페이지 + 문맥 + 피드백. 피드백은 입력이 아니라 감독 신호 | 문맥 + 정답 페이지(다음 7일 구매). 피드백 = 구매 | 🔶 노출 로그가 없다(PLAN) |
| 이벤트 4토큰 `[Entity][Action_Type][Action_Time_Bucket][Action_Duration_Bucket]` | 3토큰 `[상품][채널][며칠 전]` | ❌ **넷째 토큰(참여의 크기)이 없다.** 구매의 크기에 해당하는 값은 가격이다 → `PRICE_구간` 을 넣는다 |
| 행동은 명시(재생 · 찜 · 좋아요) + 암시(예고편 · 상세 방문) | 매장 · 온라인 구매만 | 🔶 조회 · 클릭 로그가 없다 |
| 프로필(언어 · 프로필 종류), 요청(시각 · 요일 · 기기) | 나이 · 회원 · 뉴스 · FN · 활성 / 요일 · 월 | 🔶 기기 · 시각 없음 |
| 구간 시작 특수 토큰, 연속값은 구간화 | 같음 | ✅ |
| 행 하나 · 상품 하나 = 토큰 하나, 배치 순서(왼→오, 위→아래) | 같음 | ✅ |
| 어휘를 매일 갱신, 끝내 어휘 밖이면 의미 임베딩 융합 + 대체 토큰 | 기준 시각 어휘 고정 | 🔶 매일 갱신은 C3 에서 |

## 모델 · 학습

| 원문 | 구현 | 판정 |
|---|---|---|
| decoder-only, 입력 · 출력 가중치 분리 | 같음 | ✅ |
| 사전학습 = 문맥 + 페이지 앞부분 → 다음 페이지 토큰 | 같음(페이지 토큰에만 손실) | ✅ |
| 의미 임베딩 융합: ID 임베딩 + 콘텐츠 임베딩을 입력으로 | 같음(e5 투영을 더함) | ✅ |
| 작은 확률로 **상품** 토큰을 대체 토큰으로(콘텐츠만으로 추천하도록) | 5% | ✅ |
| 작은 비율의 **알려진 토큰**을 **그 종류의** 대체 토큰으로(행은 `[Row_Fallback]`) | 상품만 바꾼다 | ❌ 행 대체가 없다 → 행도 같은 확률로 `ROW_FALLBACK` |
| 문맥 주입: 새 · 시기성 엔티티의 메타데이터를 문맥에 | 없음 | ❌ → C3(콜드 스타트) 에서 `SEP_NEW` 구간으로 |

## 원문 발견 1 의 실험 설계

| 원문 | 기존 B 계획 | 판정 |
|---|---|---|
| 모델 크기 스윕 120M → 900M(7.5배), 사전학습 손실 · WBC 손실 | small · large 를 **이력만** 문맥으로 | ❌ 원문은 문맥을 고정하고 크기만 바꾼다. 크기 비교는 **전체 문맥**에서 small · base · large |
| 문맥 풍부화: 크기 고정, 데이터 원천을 **하나씩 더한** 누적 곡선(그림 6) | 이력만 대 전체, 두 점 | ❌ → small 에서 상품 → +행동 → +시각 → +가격 → +프로필 → +요청(= 전체) 6점 |
| 비교 지표는 손실(사전학습 · WBC) | 검증 MAP@12 + 페이지 손실 | 🔶 손실을 주 지표로, MAP@12 를 같이. WBC 손실은 C1 에서 같은 비교를 다시 한다 |

## 후학습 · 운영 (C 단계 계획에 반영)

| 원문 | 반영 |
|---|---|
| WBC: 부호 = 라벨, 크기 = 가중치, 토큰 로짓에 가중 BCE, 행 보상 = 행 상품 보상 합, 탐욕 생성 | C1 그대로 |
| "사전학습이 도움이 되나": WBC 를 사전학습 있이 · 없이, 손실 · 행 AUC · 상품 AUC | **C1 에 추가** |
| 크기 · 문맥 스윕을 WBC 손실로도 | **C1 에 추가**(가능한 범위) |
| RL: 보상 모델(사전학습 체크포인트에서 시작, 페이지 보상 = 상품 보상 합) · Dr. GRPO · 정책/참조 = 사전학습 체크포인트 · KL · 형식 보상(행 목록 모양, 중요한 행이 너무 아래로 가지 않게) | C2 그대로. 다양성 = 페이지 안 상품 쌍 임베딩 거리 |
| 다중 주기: 주기적 대규모 사전학습 + 후학습, 사이에는 **후학습을 전날 체크포인트에서 이어** 그날 데이터 + 과거 표본 | C3 를 "후학습 이어가기"로 명시 |
| 온라인: 기존 후보 집합 위에서 디코딩, 지연 20% 감소 | C4 · D |

## 고친다 (B 를 다시 돌리기 전에)

1. 이벤트 넷째 토큰 `PRICE_구간`(학습 기간 가격 분위수 8구간). 이벤트 폭 3 → 4, MAXLEN 256 → 320(문맥 12 + 60 × 4 + 페이지 최대 55 = 307)
2. 행 대체 토큰: 학습 중 행 토큰도 `fallback_prob` 로 `ROW_FALLBACK`
3. 문맥 수준 6단계(`items` · `+action` · `+time` · `+price` · `+profile` · `full`)를 한 함수로 만들고 학습과 평가가 같은 함수를 쓴다
4. B 비교를 원문 설계로: 문맥 스윕(small, 6점) + 크기 스윕(전체 문맥, small · base · large)
5. C1 에 "사전학습이 도움이 되나"와 행 · 상품 AUC, C3 에 문맥 주입, C4 에 세션 행동을 넣는다
