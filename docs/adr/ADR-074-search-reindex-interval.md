# ADR-074. 검색 전체 재색인 주기 — 이벤트 유실 대비 신선도 대 재색인 비용

- 상태: 채택(비교 실험, 프로덕션 미배선)
- 날짜: 2026-09-28
- 관련: `RefreshingLuceneSearch`(ADR-056, #246), [ADR-073](ADR-073-settlement-batch-partition-strategy.md)(같은 27절 실험 방법론), 이슈 #426, `ReindexIntervalExperimentTest`

## 맥락

`RefreshingLuceneSearch`는 이벤트로 색인을 갱신하면서 별도로 전체 재색인 주기를 둔다(ADR-056). 지금 주기는 "통째로 만드는 편이 단순하다"는 근거뿐이라 숫자로 정한 적이 없다.

Instacart는 "검색 결과에 뜬 상품 중 오래된 것만 그 자리에서 갱신"하는 lazy refresh로 적재 부하를 2/3 줄였지만, 드물게 검색되는 상품·품절 상품도 갱신 기회를 얻도록 전체 동기화를 하루 여러 번 남겼다. 이벤트 갱신이 항상 성공하면(유실 0) 전체 재색인은 색인 정확도에 기여하지 않는다. 하지만 이벤트가 일부 유실되면(컨슈머 크래시 등) 그 상품의 색인은 다음 전체 재색인이 와야 정답으로 돌아온다. 이 실험은 그 "정정까지 걸리는 시간(staleness)"과 재색인 비용(수행 횟수)의 트레이드오프를 쟀다.

## 측정 방법

`ReindexIntervalExperimentTest`(`@Tag("experiment")`, 순수 JUnit, Docker 불필요, `RefreshingLuceneSearch`에 배선하지 않음)로 **가상 시계**를 썼다 — 실제 `Thread.sleep`·Lucene 색인 없이 이벤트·재색인 틱의 시간표를 산술로만 계산해, 이 기계의 다른 부하와 무관하게 결정적이고 즉시 끝난다.

- 초당 10건(원문과 동일) 변경 이벤트를 2시간(7200초, 가상) 관측했다(총 72000건).
- 유실률 0 · 1 · 5%로 각각 어느 이벤트가 유실됐는지 정하고(고정 시드), 같은 유실 패턴을 재색인 주기마다 재사용했다 — 트래픽 자체가 아니라 재색인 정책만 바꿔 비교했다.
- 전체 재색인 주기 60 · 300 · 1800초(1·5·30분) · 0(끔)을 비교했다.
- staleness = 유실된 이벤트 시각부터 그 이벤트 시각 이후 가장 가까운 재색인 틱까지의 간격. 재색인 틱이 관측 종료(7200초) 전에 오지 않으면 "회복 안 됨"으로 센다.

판정 기준은 측정 전 [이슈 #426](https://github.com/dj258255/BE-commerce/issues/426)에 적었다.

## 가설 판정

측정 전 이슈 #426에 적은 다섯 가지 전부 맞았다.

1. **맞았다.** 유실률 0%에서는 어느 주기에서도 유실 이벤트가 0건이고 staleness p99도 0이다.
2. **맞았다.** 같은 주기(300초)에서 유실률이 오를수록(0→1%→5%) staleness p99가 0→296.5s→297.1s로 커진다(1%와 5% 사이는 거의 같다 — 둘 다 균등 도착이라 주기 안에서의 상대 위치 분포가 비슷해서다. 유실 건수 자체는 720→3555로 뚜렷이 늘었다).
3. **맞았다.** 같은 유실률(5%)에서 주기가 짧을수록 staleness p99가 59.4s(60초 주기) < 297.1s(300초) < 1777.1s(1800초)로 뚜렷이 줄었다 — p99가 대략 주기 길이에 근접하는 것도 이론과 일치한다(균등 도착에서 최악은 틱 직후 유실).
4. **맞았다.** 주기가 짧을수록 재색인 수행 횟수가 120(60초) > 24(300초) > 4(1800초)로 뚜렷이 늘었다 — 신선도와 비용이 실제로 맞바꿔지는 관계다.
5. **맞았다.** 재색인을 끄면 유실률 1%·5% 모두 회복 안 된 유실 문서가 각각 720건·3555건(유실 건수 전부)으로, 관측 종료까지 하나도 정정되지 않았다.

## 이 실험이 답하지 못하는 것

- 실제 Lucene 색인·재색인 동안의 검색 p99 영향은 재지 않았다(가상 시계 시뮬레이션이라 실제 검색 성능과 무관하다). 확인 못 함.
- 적재 쿼리가 결제 p95에 주는 영향은 재지 않았다. 확인 못 함.
- 상품 10만 개 규모의 실제 색인 문서는 만들지 않았다. 이벤트·재색인 틱의 시간표만 계산했다.
- `RefreshingLuceneSearch`에 실제로 배선하지 않았다. 26·27절의 다른 실험과 같은 스코프로, 비교 근거만 남긴다.
- 재고·가격의 신선도(3장 GenPage 품절 확인 시점)는 넣지 않았다. 문서 자체(노출·분류·텍스트)로 한정했다.
- p99 staleness가 이론적으로는 주기 길이에 근접해야 한다는 것을 이 실험이 재확인했을 뿐, "목표 5분 안"이라는 원문의 결정 기준을 이 저장소의 실제 이벤트 유실률에 대입해 운영 기본값을 정하지는 않았다 — 실제 유실률(컨슈머 크래시 빈도)을 관측한 적이 없어 확인 못 함.
