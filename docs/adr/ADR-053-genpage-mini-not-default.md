# ADR-053. 작은 GenPage 모델을 만들어 서빙까지 붙이고, 기본값으로는 켜지 않는다

- 상태: **기각(기본값 미채택)**. 코드·모델 서버·홈 연결은 남긴다. `app.recommendation.model.kind=genpage` 로 켠다
- 날짜: 2026-09-24
- 관련: `personalization/pipeline/train_genpage.py`, `personalization/serving/genpage_server.py`, `GenPageModelClient`,
  `GenPagePageClient`, `RecommendationFacts#generatePageRows`, `HomeComposer#composeGenerated`,
  [실측 리포트](../../personalization/docs/runs/hm-genpage-report.md), [ADR-048](ADR-048-als-model-not-adopted.md), 이슈 #238

## 맥락

Netflix GenPage 는 사용자 이력을 프롬프트로 두고 홈 전체(행과 상품)를 한 토큰씩 생성한다. 이 저장소는 GenPage 의 서빙 쪽 —
생성 중 제약(ADR-050), 생성 범위(ADR-040), 세션 신호(ADR-035), 페이지네이션(ADR-052) — 을 만들었지만 모델 쪽이 비어
있었다. `ModelClient` 뒤에는 스텁이 있었고 ALS 는 선을 못 넘었다(ADR-048).

## 결정

**작동하는 가장 작은 GenPage 를 만들고, 서빙 계약 안에 붙이고, 기본값으로는 켜지 않는다.**

- 사전학습만 한다(다음 상품 예측). 후학습(가중 이진분류·강화학습)은 노출·보상 로그가 없어 하지 않는다
- 추론은 GenPage 를 따른다: 상품 분포를 대분류별로 합쳐 행을 고르고, 행의 앞 2개만 한 칸씩 생성하고(하이브리드 행 디코딩)
  나머지는 한 번에 고른다. 이미 나온 상품·앞 쪽 상품·다른 대분류 상품은 매 단계 마스크로 막는다
- **품절은 모델이 모른다.** 모델은 교체 가능한 의존성이고 재고를 알 이유가 없다. 앱이 생성 뒤에 거른다(ADR-050 과 같은 결론)
- 모델 서버가 느리거나 죽으면: 추천 행은 기존 폴백(인기), 홈 다음 쪽은 규칙 행(대분류 인기)으로 물러선다. 실패는 지표로 센다
- 서버가 스스로 센 규칙 위반이 0 이 아니면 그 페이지를 쓰지 않는다

## 판정 (이슈에 측정 전에 적은 기준)

| 기준 | 결과 | |
|---|---|---|
| MAP@12 ≥ 0.023354(마지막 구매 재추천, ADR-048 과 같은 선) | 0.020937 (선의 90%) | **못 넘었다** |
| 홈 한 쪽 p95 ≤ 300ms | 86~94ms (규칙 행 124ms) | 넘었다 |

둘 중 하나를 못 넘었으므로 기본값은 스텁 그대로다.

## 무엇을 알게 됐나

- **순서를 보는 모델이 행렬 분해보다 훨씬 낫다.** 같은 데이터·같은 채점기에서 ALS 최고 0.007608 의 2.8배다
- **그래도 재구매 규칙을 못 이긴다.** 이미 산 상품을 빼면 63% 떨어진다 — 점수의 상당 부분이 재구매 흉내다. ALS 에서 본 모양이 그대로다
- **하이브리드 디코딩이 왜 있는지가 비용으로 보인다.** 3행 × 8개를 전부 한 칸씩 만들면 순전파 27번(p95 46ms), 앞 2개만이면 9번(19ms)
- **생성 중 마스크는 위반 0 을 냈다.** 앱이 DB 로 다시 대조한 모델 행 685개에서 중복·대분류 불일치 0

## 버린 것

| 안 | 이유 |
|---|---|
| 에폭을 더 늘려 선을 넘긴다 | 같은 홀드아웃을 보고 세 번 골랐다(초기화 → 에폭). 여기서 더 고쳐 넘기면 홀드아웃에 맞춘 것에 가깝다. 검증 기간을 따로 떼는 것이 먼저다 |
| 모델에 재고를 넘겨 생성 중에 막는다 | 모델 계약이 재고를 알아야 한다. ADR-050 에서 이득 없이 6배 비쌌다 |
| 후학습을 합성 노출로 한다 | 합성 노출은 학습 근거로 쓰지 않는다(데이터 계약 00-data.md) |
| Hugging Face 의 Amazon 리뷰를 섞는다 | H&M 상품과 공통 ID 가 없고, Amazon_Fashion 은 카테고리 메타 0% · 가격 6% 다(00-data.md) |

## 다시 볼 조건

- 검증 기간을 따로 떼고 거기서 튜닝한 뒤 홀드아웃을 한 번만 봐서 선을 넘으면 → 켤 후보. 그다음 판정은 온라인 A/B
- 노출·클릭 로그가 실사용자에게서 쌓이면 → 후학습(페이지 수준 보상)을 검토
- 콘텐츠 임베딩(상품 설명·이미지)을 넣어 신규 고객·신규 상품을 다룰 때 → 같은 선으로 다시 잰다
