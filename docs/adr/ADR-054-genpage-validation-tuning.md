# ADR-054. GenPage 를 검증 기간으로 다시 튜닝했고, 결론은 그대로다

- 상태: **기각 유지(기본값 꺼짐)**. ADR-053 의 결정을 튜닝 방식을 바꿔 다시 확인했다
- 날짜: 2026-09-24
- 관련: `personalization/pipeline/train_genpage.py`(`GENPAGE_MODE=validate|final`),
  [리포트](../../personalization/docs/runs/hm-genpage-report.md), [ADR-053](ADR-053-genpage-mini-not-default.md), 이슈 #242

## 맥락

ADR-053 은 같은 홀드아웃을 보고 세 번 골라(초기화 → 에폭) 선의 90% 에서 멈췄다. 더 튜닝해서 선을 넘기면 모델이 나아진 것인지
홀드아웃에 맞춘 것인지 가를 수 없었다. 그래서 검증 기간을 따로 떼고 다시 했다.

## 무엇을 했나 (측정 전에 이슈에 적었다)

- 학습 기간의 마지막 7일(2020-09-09 ~ 15)을 **검증**으로 떼고, 그 이전으로 학습해 검증 점수로 설정을 골랐다
- 범위: 차원 {64, 128} × 에폭 {2, 4, 6, 8}. 규칙: 검증 MAP@12 최고, 0.0005 안이면 작은 차원 · 적은 에폭
- 고른 설정으로 홀드아웃 이전 전체를 다시 학습하고 **홀드아웃은 한 번만** 채점했다

## 결과

| | 검증 | 홀드아웃 |
|---|---:|---:|
| 검증 최고(차원 128 · 4에폭) | 0.021300 | 보지 않음 |
| **고른 설정(차원 64 · 6에폭)** | 0.021086 | **0.020930** |
| 재구매 규칙(선) | 0.023583 | 0.023354 |

- **선을 넘지 못했다**(89.6%). 기본값은 켜지 않는다
- 검증과 홀드아웃의 차이가 0.7% 라 검증 주가 제 역할을 했다
- ADR-053 이 홀드아웃을 보고 고른 값(0.020937)과 거의 같다 — **결론이 튜닝 방식에 기대지 않는다**
- 차원 128 은 8에폭에서 내려갔다. 이 데이터에서 크기나 학습량을 더 늘릴 근거가 없다

## 참고로만 잰 것: 재구매 우선 + 모델 채우기

재구매 규칙이 채우지 못한 칸을 모델로 채우면 홀드아웃 0.023779 로 규칙보다 **1.8%** 높다. 모델이 더하는 몫이 있다는 뜻이다.
그래도 채택 후보로 두지 않았다. 규칙이 쓰는 **구매 이력이 서빙 입력에 없다** — 온라인 컨텍스트에는 조회·클릭만 있다.
오프라인에서 잰 경로와 나가는 경로가 다르면 잰 값이 나가는 값을 말해 주지 않는다.

## 함께 드러난 결함

모델은 구매 시퀀스로 학습했는데 서빙은 조회·클릭 이력을 넣는다(ADR-053 에 덧붙였다). 품질 선을 넘더라도 켤 수 없던 이유다.

## 다시 볼 조건

- 주문 모듈이 사용자별 최근 구매를 내주는 경로가 생기면 → 혼합(재구매 우선 + 모델)을 **서빙 경로로** 다시 잰다. +1.8% 가 나가는 값으로도 나오는지가 질문이다
- 조회·클릭 로그가 실사용자에게서 쌓이면 → 그 로그로 학습해 입력 차이를 없앤다
