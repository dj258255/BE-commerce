# ADR-068. 넷플릭스 GenPage 를 옮긴 v2 도 선을 넘지 못해 기본으로 켜지 않는다. 백엔드 경로는 v2 로 다시 쟀다

- 상태: **채택**(v2 모델은 기본으로 켜지 않는다). 서빙 서버 · 문맥 구성 · 재고 확인 옵션은 남긴다
- 날짜: 2026-09-26
- 관련: [계획](../../personalization/docs/genpage-v2/PLAN.md) · [원문 대조](../../personalization/docs/genpage-v2/AUDIT.md) · [진행 · 결과](../../personalization/docs/genpage-v2/STATUS.md) · [백엔드 실험](../../personalization/docs/genpage-v2/BACKEND.md), [ADR-053](ADR-053-genpage-mini-not-default.md) · [ADR-054](ADR-054-genpage-validation-tuning.md) · [ADR-050](ADR-050-post-filter-over-constrained-generation.md) · [ADR-065](ADR-065-admission-by-observed-throughput.md), 마일스톤 GenPage v2, 이슈 #296 ~ #318

## 맥락

v1(ADR-053)은 상품 토큰만 있는 작은 모델로, 측정 전에 정한 선(마지막 구매 재추천 MAP@12 0.023354)을 넘지 못해 서빙까지 붙이고 껐다. v2 는 넷플릭스 GenPage(2026-06) 의 구성을 H&M 데이터가 허락하는 데까지 옮겼다 — 행 · 상품 토큰, 이벤트 4토큰 `[상품][채널][며칠 전][가격]`, 프로필 · 요청 토큰, 입력 · 출력 가중치 분리, 의미 임베딩 융합 + 상품 · 행 대체 토큰, 페이지 토큰 사전학습, 제약 디코딩 · 하이브리드 행 디코딩 · KV 캐시, 행 고정 · 운영 후보 집합, WBC.

이 프로젝트의 본래 질문은 모델 성능이 아니라 **모델이 request path 에 들어왔을 때 백엔드가 무엇을 보장하는가**다. 다만 모델이 단순 규칙보다 못하면 그 모델을 request path 에 넣을 이유를 설명할 수 없어, 선을 넘는 것을 목표로 순서와 기한을 측정 전에 정했다(PLAN "선을 넘기 위한 순서").

## 판정 기준 (측정 전에 적었다)

검증 주(2020-09-09 ~ 15)로만 고르고, 고른 설정 하나로 final 데이터(학습 < 2020-09-16)에서 다시 학습해 홀드아웃 주(68,984명)를 **한 번** 본다. 선 0.023354(v1 기록)와 v2 하네스의 재구매 값 0.023446 을 **둘 다** 넘으면 "선을 넘었다". 못 넘어도 다시 고르지 않는다(ADR-054).

## 결과 (대입)

| 홀드아웃(68,984명) | MAP@12 | 이력에 어휘 상품이 있는 고객만 | 페이지 recall | 규칙 위반 |
|---|---|---|---|---|
| **v2**(base · 전체 문맥 · 1에폭 + 다시 사기 행 고정) | **0.019268** | 0.020351 | **0.0691** | 0 |
| v1 모델(ADR-053) | 0.020930 | 0.022770 | 0.0401 | — |
| 마지막 구매 재추천(선) | **0.023354**(기록) · 0.023446(하네스) | 0.025508 | 0.0405 | — |
| 지난주 인기 | 0.008748 | 0.008825 | 0.0255 | — |

**선을 넘지 못했다(선의 83%). v1 보다도 낮다.** 페이지 전체(최대 48개)가 맞힌 비율은 선의 1.7배지만, MAP@12 는 앞 12개의 순서로 매기고 그 자리에서 "최근 산 순서대로 다시 보여 주기"를 이기지 못했다.

검증 주에서 거친 순서(같은 1만 명 표본, 선 0.02346): 모델 단독 0.01017 → 다시 사기 행 고정 0.01865 → 운영 후보 집합 0.01870 → WBC **0.00276**(노출되지 않은 토큰의 사전학습 로짓이 이겨 무너졌다) · 2에폭 0.01959(1에폭과 차이 0.001 안이라 규칙대로 1에폭).

원문의 오프라인 발견 1 은 **반대로 나왔다** — 문맥을 하나씩 더해도 손실이 줄지 않았고(+0.27%), 모델을 2.2배 키우니 7.5% 줄었다(원문: 문맥 누적 6.9%, 크기 7.5배 1.3%).

## 결정

- **v2 모델은 기본으로 켜지 않는다.** `app.recommendation.model.kind` 기본값(stub)과 v1 설정은 그대로 둔다
- **서빙 경로는 남긴다.** `serving/genpage2_server.py`(v1 과 같은 HTTP 계약)로 앱의 모델 주소만 바꾸면 v2 가 붙는다. 백엔드 실험 네 개는 이 경로로 쟀다
- 백엔드 실험의 결론(`BACKEND.md` 결과 절)
  - **X2** 입장 제한(ADR-065)은 v2 에서 값이 뚜렷해졌다 — 모델이 병목이 되자(초당 23건, v1 의 1/43) 제한 없이는 대기 한도를 넘긴 뒤 폴백해 p95 576 ms, 제한하면 같은 개인화 비율에서 243 ms. **그대로 기본이다**
  - **X3** 모델 출력을 그대로 믿으면 응답의 80% 이상에 품절이 섞인다. 지금 방식(`POST`, ADR-050)이 99.9% 를 거른다. 응답 직전 재확인(`POST_FINAL`)은 품절 10/s 에서만 0.06% → 0% 로 차이가 났고 3/s 에서는 같았다(0.12%). **기본은 `POST` 로 둔다** — 차이가 한 조건 · 품절 후보 36개의 좁은 실험에서만 났고, 품절이 없을 때도 요청당 재고 조회가 0.5회(약 1.3 ms) 는다. 추천 화면의 극소수 품절은 결제 시점 재고 차감(ADR-003)이 최종으로 막는다
    - `POST_FINAL` 을 켤 조건: 품절이 잦은 상품군(한정 수량 · 드롭 판매)이 생겨 추천 화면의 품절 노출이 클릭 뒤 품절 안내로 실제 이어지는 것이 관측될 때, 그 상품군의 노출률로 다시 잰다
  - **X1** 서빙은 학습과 같은 함수로 문맥을 만들어 토큰까지 일치한다. 지금 앱이 주는 상품 id 목록만으로는 입력이 학습 때와 51% 다르다 — v2 를 켤 때는 구매 시각 · 가격 · 프로필을 공급해야 학습 때와 같은 출력을 얻는다
  - **X5** 지금 설정(`app.recommendation.genpage-session: OFF`)으로 v2 를 켜면 조회 · 클릭이 전부 요청일의 구매로 들어가고, 홈의 8건 창(`app.home.context-limit`) 때문에 오래된 행동이 빠진다(20명 중 20명). `RICH` 는 기준 조건에서 20명 전원이 토큰까지 일치했다. **v2 를 켤 때는 `RICH` 를 같이 켠다.** 기본은 `OFF` 로 둔다 — v2 는 기본이 아니고 v1 서버는 `session` · `now` 를 읽지 않는다(`personalization/docs/runs/20260926-v2-x5-replay/report.md`)
  - **X4** 300 ms 예산 안에서는 원문 하이브리드(행마다 앞 2개만 한 칸씩, KV 캐시)가 6행을 202 ms 에 만든다. 전부 한 칸씩은 357 ms 로 넘는다

## 대가 · 한계

- 규모: 원문 2억 ~ 9억 파라미터를 GPU 클러스터에서, 여기는 4,700만(base)을 노트북 한 대에서 4,500단계. large(7,800만)는 시간 때문에 뒤로 미뤘다
- 노출 로그가 없다. 사전학습 정답은 "다음 주에 산 것"이고 WBC 라벨도 실제 구매다. WBC 는 노출 1만 페이지 · 79단계로 노출 범위가 좁아 무너졌다
- 측정 조건: 맥 메모리 압박(스왑 약 20GB) · 다른 프로젝트 컨테이너가 도는 상태. 지연 절대값은 조용한 장비보다 클 수 있다

## 다시 볼 조건

- WBC 를 노출 범위를 넓혀(표본 · 탐색) 또는 사전학습 손실과 함께 다시 해 검증 주에서 선을 넘을 때(#301)
- RL(#302) · large · 더 긴 학습으로 검증 주에서 선을 넘을 때
- 실제 사용자의 노출 · 반응 로그가 쌓여 "다음 주 구매"가 아닌 노출 반응으로 학습할 수 있을 때
