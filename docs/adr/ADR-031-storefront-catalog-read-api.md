# ADR-031. 쇼핑몰 카탈로그를 읽기 전용으로 연다

- 상태: 채택
- 날짜: 2026-09-19
- 관련: `CatalogController`, `CatalogQueryService`, `Product`, `Category`, `V53`·`V54`, [ADR-017](ADR-017-aggregate-boundaries.md), [ADR-010](ADR-010-what-not-to-build.md)

## 맥락

화면을 결제 데모 콘솔에서 이커머스 쇼핑몰로 넓히면서, 홈·카테고리·검색·상세가 **상품을 탐색할 표면**이 필요해졌다. 그런데 `products`는 지금까지 **가격의 서버 측 원천**으로만 쓰였다 — 주문 생성이 `findById`로 한 건씩 읽을 뿐, 목록·카테고리·검색 조회가 없었고 카테고리·설명·이미지 개념도 없었다.

상품을 화면에 채우는 방법은 셋이었다. ① 프론트에 목데이터를 박는다 ② 정적 JSON을 둔다 ③ 서버가 카탈로그를 조회해 준다. 이 저장소는 데모 콘솔에서 **"미리 준비한 응답이 아니라 실제 API 호출"** 을 내세워 왔다. 목데이터를 박으면 그 서사가 거짓이 된다.

## 결정

### 1. 읽기 전용 공개 카탈로그 API를 둔다

`GET /api/v1/categories`, `GET /api/v1/products`, `GET /api/v1/products/{id}` 세 표면을 연다.

- **인증이 필요 없다.** 상품 탐색은 로그인 전에 되어야 한다. 주문·결제만 `ROLE_USER`를 요구한다.
- **쓰기 표면은 두지 않는다.** 상품 등록·수정 API 없이 시드와 마이그레이션으로만 채운다.
- **가격·재고의 권위는 그대로 주문·결제 경로에 남는다.** 카탈로그는 표시용 속성만 읽는다. 클라이언트는 여전히 가격을 보내지 않고, 주문 생성이 `products`에서 가격을 확정해 `order_items` 스냅샷으로 굳힌다.

### 2. 탐색용 속성만 테이블에 더한다

`categories` 테이블을 만들고 `products`에 `category_code`·`description`·`image_url`·`brand`·`featured`·`created_at`을 더한다. `category_code`는 FK 제약 없이 인덱스만 둔다(ERD §10 규칙).

### 3. 화면은 정적 다중 페이지로 만든다

SPA·번들러를 도입하지 않는다. Spring이 정적 파일을 그대로 서빙하고, 화면은 상대 경로로 API를 부른다(same-origin, CORS 불필요).

## 버린 것 (대안과 대가)

| 대안 | 버린 이유 |
|---|---|
| **별도 `catalog` 모듈** | ADR-017이 "주문·상품·재고는 애그리거트 분리(모듈 분리 아님)"로 정했다. 상품은 이미 재고와 키 공간을 공유하고 주문 생성이 직접 읽는다. 모듈로 떼면 경계·이벤트·`package-info` 비용만 늘고 얻는 게 없다 |
| **상품 관리(쓰기) API** | 공개 데모에 관리자 상품 등록은 범위 밖이다. 가격 변경 경로를 열면 "검증 기준값은 주문 시점 스냅샷"이라는 계약을 다시 설명해야 한다. 시드로 충분하다 |
| **전문 검색(형태소·Elasticsearch)** | 카탈로그가 수십 건이다. `LIKE` 부분 일치로 충분하고, 검색 엔진은 [ADR-010](ADR-010-what-not-to-build.md)의 "만들지 않는 기준"에 걸린다 |
| **SPA(React·Vite·Next)** | 빌드 도구와 별도 서버가 필요하다. 기존 정적 서빙이 "목적에 맞는 최소 도구"라는 판단을 유지한다 |

**대가:** 검색은 형태소 분석이 없어 "이어폰"과 "이어 버드"를 다른 말로 본다. 재고 표시는 참고용이라, 품절 판정과 실제 차감(승인 시점) 사이에 시차가 있다.

## 성공 기준

> 비로그인 상태로 카테고리 목록·상품 목록·검색·상세가 조회되고, 카테고리 필터·검색·정렬·페이지네이션·품절 표시가 실제 응답으로 동작한다. 없는 상품 상세는 404 `PRODUCT_NOT_FOUND`. `CatalogQueryServiceTest`가 정렬·필터 위임과 재고 표시를 고정한다.

## 정직한 한계

- **쓰기 표면이 없다.** 상품을 바꾸려면 마이그레이션을 추가해야 한다. 데모 범위에서 의도한 것이다.
- **`inStock`은 조회 시점의 스냅샷이다.** 승인 시점 차감(ADR-003)과 별개라, 조회와 결제 사이에 품절될 수 있다. 최종 판정은 승인의 조건부 차감이 한다.
- **검색은 부분 일치다.** 오타 교정·동의어·랭킹이 없다.

## 다시 볼 조건

- 카탈로그가 커져 `LIKE '%…%'`가 느려지면 → 인덱스 전략 또는 전문 검색 도입을 ADR로 다시 판단한다.
- 상품 등록·가격 변경이 실제 요구가 되면 → 쓰기 API + 감사 로그 + 가격 스냅샷 계약 재정의를 함께 설계한다.
