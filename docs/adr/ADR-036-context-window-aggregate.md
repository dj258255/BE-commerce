# ADR-036. 창 집계를 목록과 분리한다 — 세는 일에는 세는 그릇을 준다

- 상태: **채택**
- 날짜: 2026-09-21
- 관련: `ContextStore`, `OnlineContext.counts`, [ADR-035](ADR-035-order-tolerant-context-merge.md), `personalization/docs/runs/20260921-e2-online-offline-일치율/report.md`, `personalization/docs/runs/20260921-e2f-창집계-재측정/report.md`

## 맥락

온라인 컨텍스트는 활동 목록을 **`max-items`(기본 20)로 잘라** 담는다. 화면에는 "최근 본 것 몇 개"만
필요하므로 그 자체는 맞는 설계다.

문제는 **창 집계를 그 목록에서 세고 있었다**는 것이다. "이 사용자가 최근에 상의를 몇 번 봤나"를
목록 길이로 답하면, 목록이 꽉 찬 순간부터 답이 틀린다. E2가 그걸 쟀다 — 활동이 30건인 사용자에서
**목록은 100% 맞는데 집계는 60%만 맞았다**(`window` 조건). 그릇이 하나면 **잘림과 집계가 같이 망가진다.**

E2의 대조 도구도 같은 실수를 했다 — `len(online_items) == len(log_rows)`로 창을 셌다.
**재는 쪽과 재지는 쪽이 같은 잘림을 물려받았다.**

## 결정

**컨텍스트가 유형별 카운터(`counts`)를 함께 담는다.** 목록과 달리 **잘리지 않는다.**

- `counts` = `{활동 유형: 수}`, **창은 컨텍스트의 수명, 즉 TTL이다**(기본 7일). 키가 만료되면 창도 초기화된다
- 갱신은 **목록과 같은 Lua 안에서** 한다 — 따로 저장하면 둘이 어긋나는 순간이 생긴다
- 중복 제거가 **병합 전에** 걸리므로 재배달은 두 번 세어지지 않는다. 늦게 온 이벤트는 실제로 일어난
  일이므로 한 번 세어진다 → **집계도 순서에 무관**하다(ADR-035의 짝)

## 근거

### 1. 같은 조건을 다시 재면 60% → 100%다

```
| 조건 | 대상 | 컨텍스트 일치율 | 창 집계 일치율 |
|---|---:|---:|---:|
| window | 20명 | 100.0% | 100.0%   ← 이전 60.0%
```

### 2. 재는 도구도 함께 고쳐야 했다

도구가 목록 길이로 창을 세고 있었으므로, 앱만 고치면 **좋아진 것을 볼 수 없다.** 대조 도구를
**유형별 카운터 비교**로 바꾸고, `truncated`를 **불일치 원인에서 관찰로 내렸다** — 목록이 잘리는 것은
이제 정상 동작이고, 원인 목록에 남겨 두면 "집계가 틀렸다"는 옛 의미로 읽힌다.

**정의가 바뀌면 그 열의 옛 수치와 같은 표에 놓을 수 없다.** 그래서 E2-f에서 **전 조건을 새 도구로
다시 쟀다.** 이전 리포트(E2·E2-c·E2-e)의 "창 집계 일치율"은 **목록 길이 기준**이었다는 것을 밝힌다.

### 3. 집계를 따로 저장하지 않은 이유

Redis의 별도 키나 해시로 두면 **목록과 집계가 어긋나는 순간**이 생긴다(하나만 쓰이고 다른 하나가
실패). 같은 값 안에서 같은 스크립트로 갱신하면 그 순간이 없다 — 대가는 컨텍스트 값이 조금 커지는 것뿐이다.

## 대가 (정직하게)

- **창이 슬라이딩이 아니라 TTL 경계다.** "최근 7일"이 아니라 "활동이 이어진 최근 7일"이다 —
  활동이 끊기면 창이 초기화된다. **진짜 슬라이딩 창(예: 시간 버킷)은 만들지 않았다**
- **컨텍스트 값이 커진다.** 유형 수만큼 늘어난다(현재 유형은 소수라 무시할 수준이지만 **재보지 않았다**)
- **유형이 동적으로 늘어나면** 카운터도 늘어난다 — 상한을 두지 않았다. 유형이 열린 집합이 되면
  다시 봐야 한다
- **`truncated` 를 관찰로 내린 것은 도구 쪽 결정**이다. 목록이 잘리는 것을 "원인"으로 계속 보고
  싶은 소비자가 있으면 그쪽이 따로 판단해야 한다
- **집계는 "적용된" 이벤트를 센다** — 소비가 못 따라온 구간은 목록과 똑같이 빠진다(`late` 조건이 그 예다).
  집계가 목록보다 정확해지는 것이 아니라 **잘림에 강해질** 뿐이다
