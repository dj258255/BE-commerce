# ADR-062. 검색 동점은 상품 id 로 끊는다: 기준(0)은 못 넘었지만 흔들림을 99% 줄였다

- 상태: **채택**(판정 기준을 엄밀히 넘지 못한 채 채택했다. 아래에 이유를 적는다)
- 날짜: 2026-09-24
- 관련: `LuceneProductSearch`, [실측 리포트](../performance/search-paging-churn.md), [ADR-056](ADR-056-search-index-freshness-by-cdc.md),
  [ADR-052](ADR-052-home-pagination-cursor.md), 이슈 #258

## 맥락

ADR-056 으로 검색 색인이 변경을 1초 안에 반영한다. 검색은 오프셋 쪽 넘김이다. 이름이 같은 상품이 많아 동점이 많고, Lucene 은 동점을 내부 문서
번호로 줄 세운다. 문서를 갈아 끼우면 번호가 바뀐다. 예측은 "검색어와 무관한 가격 변경만으로도 쪽 사이에 중복·누락이 생긴다"였다.

## 판정 기준 (이슈 #258 에 측정 전에 적었다)

- 변경 중 중복·누락이 기준선보다 많으면 동점을 상품 id 로 끊는 정렬을 넣고 다시 잰다. 가격 변경 아래 중복·누락 0 이면 채택
- 새 상품이 끼어드는 경우는 숫자만 적는다

## 결과 (대입)

결과 상품의 가격을 바꾸는 동안(쿼리 50개, 3쪽): 중복 88 → **0**, 누락 888 → **9**. 무작위 상품 가격 변경은 전후 모두 0. 새 상품 추가는 전후 모두 누락 2,000.
검색 지연은 흔들림 범위 안(동시성 10 p95 19.7·26.2ms 대 18.6·20.4ms).

## 결정

**점수 내림차순, 상품 id 오름차순으로 정렬한다.** 기준(0)은 누락 9건으로 넘지 못했다. 그래도 채택하는 이유:

- 남은 9건은 동점 정렬이 다룰 수 있는 원인이 아니다. 갈아 끼운 문서의 옛 판이 병합 전까지 단어 통계에 남아 **점수 자체가 움직인다**(단위 테스트로 고정했다)
- 이 정렬이 잃는 것을 찾지 못했다. 지연이 같고, 색인을 처음 만들 때는 문서 번호가 적재 순서(상품 id 순)라 동점 순서도 같다
- 기준을 0 으로 적은 것은 원인이 동점 하나라고 봤기 때문이다. 원인이 둘이었다는 것이 이번에 알게 된 것이다

## 버린 것

| 안 | 이유 |
|---|---|
| 그대로 두기 | 결과 상품이 바뀌는 동안 누락 30% |
| 커서 방식 검색(마지막 점수·id 다음부터) | 중복은 막지만 위로 끼어든 상품은 여전히 안 보인다. API 가 바뀐다. 이 이슈에서는 재지 않았다 |
| 변경마다 병합(`forceMergeDeletes`) | 남은 9건(점수 흔들림)을 줄일 수 있지만 변경마다 색인을 다시 쓴다. 재지 않았다 |

## 대가 (정직하게)

- 여러 단어 쿼리에서는 가격 변경만으로도 쪽 경계의 상품이 가끔 빠진다(50개 중 4개 쿼리, 9건)
- 새 상품이 위로 끼어들면 쪽이 통째로 밀린다. 오프셋 방식의 한계다
- ES·OpenSearch 쪽은 이 결정에서 바꾸지 않았다. 나중에 두 엔진의 순서 차이를 가르면서 같은 정렬을 넣었다([ADR-064](ADR-064-engine-tie-break.md))

## 다시 볼 조건

- 쪽 넘김 중 누락이 사용자 문제로 드러나면 → 커서 방식 검색을 잰다
- 엔진을 ES 로 옮기면 → 같은 하네스로 동점과 점수 흔들림을 다시 잰다(ES 도 동점 정렬은 들어갔다, ADR-064)
