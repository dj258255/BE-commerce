# ADR-063. 검색어 고치기를 만들었지만 기본으로 켜지 않는다: 한국어는 부서명 사전으로는 모자랐다

- 상태: **기각(기본값)** · 기능은 남긴다(`app.catalog.search.rewrite.enabled=false`)
- 날짜: 2026-09-24
- 관련: `QueryRewriter`, `QueryRewriting`, `CatalogQueryService`, [실측 리포트](../performance/query-rewrite.md),
  [ADR-051](ADR-051-search-engine-by-quality.md), 이슈 #260

## 맥락

ADR-051 은 품질을 속성 일치로만 쟀고 "동의어·한국어 쿼리는 재지 않았다"고 적었다. 측정 전에 확인해 보니 상품 텍스트에 한글이 있는 상품이
105,545개 중 3개다. 한국어 형태소 분석기로는 풀 수 없고, 한국어를 카탈로그의 말로 바꾸는 사전이 필요하다. 앱에는 한·영 쌍 라벨(중분류·색상)이 있다.

## 판정 기준 (이슈 #260 에 측정 전에 적었다)

1. 한국어 쿼리(G1~G3)의 0건 비율 5% 이하
2. 기존 A~E 각 묶음의 nDCG@10 이 0.01 넘게 떨어지지 않는다
3. 1·2 를 모두 지키면 기본으로 켠다

## 결과 (대입)

| | 끔 | 켬 |
|---|---:|---:|
| G1 · G2 · G3 0건 | 90% · 88% · 97% | **10% · 12% · 12%** |
| A~E nDCG@10 | — | 545개 중 바뀐 쿼리 0 |

1 을 못 넘었다 → **켜지 않는다.**

## 결정

- **검색어 고치기는 설정 뒤에 남긴다.** 한국어 라벨 사전(색상 → 필터, 중분류 → 원문 이름)과 미국식 → 영국식 목록 9개
- **기본은 끈다.** 한국어 0건이 10% 넘게 남는다. 원인은 사전의 말이다 — 중분류의 원문 이름("Knitwear", "Unknown")은 H&M 의 부서명이라 상품 텍스트에 없다
- 형태소 분석기(nori)는 넣지 않는다. 카탈로그에 한글이 없어서 한국어 쿼리가 맞을 곳이 없다

## 버린 것

| 안 | 이유 |
|---|---|
| nori 분석기 | 카탈로그 텍스트에 한글이 없다(3건) |
| 중분류 라벨 → 중분류 필터 | 0건은 없어지지만 정답이 중분류라 측정이 자기 자신을 재게 된다. 그리고 "니트"를 친 사람이 "Knitwear 부서"를 원하는지 알 수 없다 |
| 번역 모델로 쿼리 번역 | 요청마다 모델 호출이 붙는다. 검색 로그 없이 품질을 잴 방법이 없다 |

## 대가 (정직하게)

- 한국어로 검색하면 지금처럼 대부분 0건이다
- 미국식 목록은 기존 쿼리에 영향이 없었지만(0 개 변화), 그 목록 자체의 품질은 잴 수 없었다(사전 = 쿼리)

## 다시 볼 조건

- 실제 한국어 검색 로그가 쌓이면 → 자주 나오는 말을 상품 종류로 잇는 사전을 만들고 같은 기준으로 다시 잰다
- 카탈로그에 한국어 상품명·설명이 들어오면 → 그때는 nori 가 의미가 있다. 분석기를 바꾸고 다시 잰다
