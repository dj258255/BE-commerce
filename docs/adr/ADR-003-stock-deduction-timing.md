# ADR-003. 재고는 결제 승인 성공 시점에 차감한다

- 상태: 채택 (Accepted)
- 날짜: 2026-07-05
- 관련: Phase 1(주문/결제 코어), Phase 2(보상 트랜잭션)

## 맥락

주문 → 결제 흐름에서 재고를 언제 차감할지 정해야 한다. 두 시점이 있다.

- **주문 생성 시 선점**: 주문을 만들 때 재고를 미리 잠근다.
- **승인 성공 시 차감**: 결제가 실제로 승인된 뒤에만 재고를 뺀다.

## 결정

**결제 승인이 성공한 시점에 차감**한다.

```
주문 생성 → (재고 여유 확인만) → 결제 승인 → 재고 차감 → 완료
```

## 근거

1. **재고 잠김(dangling reservation)이 없다**: 선점 방식은 결제까지 안 가고 이탈한 주문이 재고를 물고 있어, 만료·해제 배치를 또 만들어야 한다. 승인 시 차감은 "돈이 실제로 움직인 것"에만 재고를 소비한다.
2. **구현이 단순**: 상태가 하나 줄고(선점 상태 불필요), 예약-해제 로직이 사라진다.
3. **실패 설계와 자연스럽게 연결**: 승인은 됐는데 재고 차감이 실패하는 경우(품절 경합) → **망취소/보상 트랜잭션**([Phase 2])으로 결제를 되돌린다. 이건 어차피 만들어야 하는 핵심 기능이라, 재고 차감을 그 위에 얹으면 별도 메커니즘이 필요 없다.

## 트레이드오프 / 포기한 것

- **승인 후 품절 가능성**: 승인이 성공했는데 그 찰나에 재고가 0이 될 수 있다. 이때는 승인을 보상(망취소)하고 사용자에게 품절 안내. 선점 방식이었다면 이 창을 없앨 수 있지만, 대신 재고 잠김이라는 상시 비용을 진다.
- **선착순/한정판**처럼 "승인 전에 반드시 재고를 확보"해야 하는 시나리오에는 부적합. 그 경우는 Phase 5에서 **Redis 대기열 + 선점**을 별도 전략으로 다룬다(같은 코드에 두 전략을 공존시켜 부하테스트로 비교).

## 후속

- Phase 1: 승인 성공 시 재고 차감. 차감 실패 시 일단 예외 → Phase 2에서 보상으로 승격.
- Phase 5: 재고 차감 동시성 실험(비관적 락 vs 낙관적 락 vs Redisson)의 대상 테이블로 재사용.

## 2026-09-26 한정 상품 부하로 잰 대가 (#374)

이 ADR 은 승인 뒤 품절의 대가(망취소)를 적어 두고 몇 건인지 재지 않았다. 재 보니 두 가지가 틀려 있었다.

- **"재고 여유 확인"이 코드에 없었다.** 위 흐름도의 "(재고 여유 확인만)"은 문서에만 있었다. 그래서 매진 뒤 결제도 PG 승인까지 가고 망취소됐다
- **결과를 모르는 결제의 재고는 10분 넘게 빠지지 않는다.** 결제 복구가 1~2분 안에 승인으로 확정해도 주문 쪽은 그 확정을 듣지 않고, 재고 차감은 주문 복구(10분 넘게 멈춘 주문)가 한다

재고 100 · 주문 300(초당 5건, 60초) · 이탈 20% · 결제의 약 10% 결과 모름(절반은 PG 에 승인, 절반은 PG 에 없음), 전략 넷을 동시에 잰 값이다. 판정 기준은 측정 전에 이슈에 적었다.

| 전략 | 망취소 | 팔지 못한 재고(부하 끝 13분 뒤) | 판매 |
|---|---:|---:|---:|
| `NONE`: 확인 없이 승인 뒤 차감(고치기 전 코드) | 116(매진 뒤 결제 100 + 결과 모름 중 승인 16) | 0 | 100 |
| **`CHECK`**: 주문 생성 때 여유만 확인(이 ADR 이 적은 흐름) | 9(전부 결과 모름 중 승인) | 0 | 100 |
| `AT_PAYMENT`: 결제 시작에 예약, 승인에 확정 | 0 | 4(PG 에 없던 결과 모름이 10분 넘게 잡고 있다 풀림) | 96 |
| `AT_ORDER`: 주문 생성에 예약(이 ADR 이 버린 안) | 0 | 24(이탈한 주문이 만료 30분까지 잡고 있음) | 76 |

네 전략 모두 초과 판매는 0 이었다(판매 ≤ 100, 재고 음수 없음, 뺀 재고 = 판매 + 잡힌 예약).

**결정**

- **기본값을 `CHECK` 로 바꿨다.** 코드를 이 ADR 이 적은 흐름에 맞춘 것이다. 망취소 116 → 9
- **`AT_PAYMENT` 는 한정 수량 상품에 켤 수 있는 설정으로 남긴다.** 망취소를 0 으로 만드는 대가가 재고 4개였다. 망취소 한 건(승인된 카드의 취소, 고객 알림)과 재고 한 개 중 무엇이 비싼지는 상품이 정한다. 일반 상품은 매진 경합이 드물어 `CHECK` 로 충분하다
- **`AT_ORDER` 는 버린 채로 둔다.** 팔지 못한 재고가 `AT_PAYMENT` 의 6배였다. 이 ADR 의 "선점은 이탈 주문이 재고를 문다"가 숫자로 섰다
- **창을 줄여도 매진이 더 빨랐다(#378)**: `CHECK` 의 망취소 9건은 전부 결과 모름이 10분 넘게 마무리되지 않는 동안 재고가 팔린 것이었다. 결제 복구가 확정하면 주문이 바로 듣고 마무리하게 해 확인 → 주문 마무리가 중앙값 약 640초에서 **108초**가 됐다. 그래도 같은 부하에서 망취소는 **9 → 8**, `AT_PAYMENT` 의 팔지 못한 재고는 **4 → 3** 이었다. 매진이 약 25초 만에 와서 2분도 길다. 한정 상품에 `AT_PAYMENT` 를 남긴 이유가 여기서 한 번 더 섰다. 원자료 [`performance/raw/20260926-s378-listen/`](../performance/raw/20260926-s378-listen/)
