# ADR-072. 재시작 직후 웜업 — 트래픽 한 번에 대 서서히

- 상태: 채택(비교 실험, 프로덕션 미배선)
- 날짜: 2026-09-28
- 관련: ADR-022(콜드/웜 비율 실측), [ADR-071](ADR-071-batch-worker-lease-vs-row-claim.md)(같은 27절 실험 방법론), 이슈 #422, `RestartWarmupExperimentTest`

## 맥락

Google SRE Book의 캐스케이딩 장애 장이 다루는 문제다. 재시작한 인스턴스에 트래픽을 한 번에 전부 돌리면, 콜드스타트(JIT 미컴파일·커넥션 풀 미충전) 상태에서 목표 트래픽을 그대로 받아 처리 시간이 늘고, 유한 용량(커넥션 풀)이 넘쳐 큐잉·타임아웃(2차 장애)이 생길 수 있다. 트래픽을 서서히 늘리면(램프) 콜드스타트 구간의 동시 부하가 낮아 같은 용량으로도 넘치지 않지만, 목표 트래픽에 도달하는 속도는 느리다.

이 저장소는 이미 ADR-022 실측에서 "워밍업이 없으면 결론이 뒤집힌다"를 확인했다. 기동 직후 첫 요청의 p95가 903ms, 워밍업 뒤 같은 설정이 99.5ms(약 9배 차이)였다. 이번 실험은 그 콜드/웜 비율을 시간에 따라 지수적으로 감쇠하는 배율로 근사해 재시작 직후 트래픽 투입 방식의 대가를 비교한다.

## 측정 방법

`RestartWarmupExperimentTest`(`@Tag("experiment")`, 순수 JUnit, Docker 불필요)로 처리 용량을 ADR-022와 같은 Hikari `maximum-pool-size`(20)로 모사했다. 콜드스타트 배율은 ADR-022 관측 비율(약 9배)에 근거해 시작값 8배로 잡고 시정수 3000ms로 지수 감쇠시켜 웜 상태(1배)에 가까워지게 했다. 목표 처리율은 콜드 상태 용량(약 125/s)을 크게 웃도는 300/s, 관측 시간 10초, 요청이 600ms 넘게 기다리면 타임아웃(2차 장애)으로 셌다.

- **IMMEDIATE**: t=0부터 목표 처리율을 그대로 투입한다.
- **GRADUAL**: t=0부터 4초에 걸쳐 0에서 목표 처리율까지 선형으로 늘린다.

**회복 시간 정의**: 세마포어(용량)를 기다린 시간이 임계값(15ms)을 넘는 마지막 완료 시각. 원시 지연에는 콜드 배율 자체(트래픽 방식과 무관하게 시간에 따라 똑같이 감쇠)가 섞여 있어, 1차 구현에서 100ms 창별 원시 지연 p95로 재다가 콜드 배율 감쇠가 두 조건 모두를 지배해 큐잉 효과가 가려지는 문제가 있었다. 대기 시간만 따로 봐서 고쳤다(아래 "함정" 참고).

판정 기준은 측정 전 [이슈 #422](https://github.com/dj258255/BE-commerce/issues/422)에 적었다.

## 실측 결과

| 지표 | IMMEDIATE | GRADUAL |
|---|---:|---:|
| 완료 건수 | 2883 | 2397 |
| 타임아웃(2차 장애) 건수 | 117 | 0 |
| p50 | 38ms | 37ms |
| p95 | 558ms | 91ms |
| 회복 시간(대기 임계값 초과 마지막 완료) | 4746ms | 0ms |

## 가설 판정

측정 전 이슈 #422에 적은 네 가지 전부 맞았다.

1. **맞았다.** IMMEDIATE의 타임아웃이 117건으로 0보다 크다. 콜드 상태의 유한 용량이 목표 처리율을 못 받아낸다는 증거다.
2. **맞았다.** GRADUAL의 타임아웃은 0건으로 IMMEDIATE(117건)보다 뚜렷이 적다.
3. **맞았다.** IMMEDIATE의 회복 시간(4746ms)이 GRADUAL(0ms, 대기 임계값을 넘긴 완료가 한 번도 없었다는 뜻)보다 길다.
4. **맞았다.** 완료 건수는 IMMEDIATE 2883건, GRADUAL 2397건으로 약 16.9% 차이(허용치 20% 이내)다. GRADUAL이 그냥 덜 일한 것이 아니라 큐잉 없이 같은 자리수로 일했다.

## 이 실험이 답하지 못하는 것

- 실제 스프링 앱 재시작·JIT·커넥션 풀은 재현하지 않았다. ADR-022가 실측한 콜드/웜 비율을 시간에 따라 감쇠하는 배율로 근사한 시뮬레이션이다.
- 램프 길이(4초)·목표 처리율(300/s)의 민감도 스캔은 하지 않았다.
- `tools/run-rolling-deploy.sh`(#338, ADR-029) 같은 실제 롤링 배포 하네스에는 연결하지 않았다. 26·27절의 다른 실험과 같은 스코프로, 비교 근거만 남긴다.
