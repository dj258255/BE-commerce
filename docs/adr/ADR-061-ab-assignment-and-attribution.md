# ADR-061. A/B 배정은 해시로 고정하고, 노출은 홈 기록에 얹고, 귀속은 노출된 상품으로 한정한다

- 상태: **채택**(기반). 실험은 기본으로 꺼져 있다(`app.experiments.rec-history.enabled=false`)
- 날짜: 2026-09-24
- 관련: `ExperimentAssigner`, `RecommendationService`, `HomeImpression`, `V68__home_impression_experiment.sql`, `tools/ab_analysis.py`,
  [검증 리포트](../../personalization/docs/runs/20260924-ab-e2e/report.md), [ADR-043](ADR-043-home-impression-log.md), [ADR-060](ADR-060-genpage-serves-purchases.md), 이슈 #256

## 맥락

추천 품질의 최종 판정은 A/B 다(트러블슈팅 기록 열린 항목 5). ADR-060 은 재구매 우선 혼합을 A/B 후보로 뒀다. 실사용자 트래픽은 나중에 붙이더라도,
실험을 돌렸을 때 **숫자가 믿을 만하게 나오는 기반**은 먼저 있어야 한다. 기반이 틀리면 실사용자 결과도 틀린다.

## 판정 기준 (이슈 #256 에 측정 전에 적었다)

고정성 · A/A 에서 차이 없음 · 주입한 차이 복원 · 노출되지 않은 상품은 세지 않음. 합성 사용자 1,000명.

## 결과 (대입)

고정 배정 위반 0(3,000번 방문) · SRM p 0.752 · 0.411 · A/A 두 구간 모두 0 포함 · 주입 A/B 두 구간 모두 주입값 포함 ·
귀속 = 정답(클릭 239 = 239, 구매 51 = 51) · 음성 대조 전부 제외. 넷 다 통과.

## 결정

- **배정은 해시로 고정한다.** `SHA-256(솔트:사용자 id)` → 0~9,999. 배정 표를 두지 않는다. 표를 두면 요청마다 쓰기가 붙고, 표와 코드가 갈라질 수 있다
- **새 실험은 새 솔트로 시작한다.** 같은 솔트를 쓰면 앞 실험의 실험군이 그대로 다음 실험의 실험군이 되어 영향이 섞인다
- **노출은 홈 1쪽 기록(`home_impressions`)에 실험·변형 두 열을 얹는다.** 따로 노출 표를 만들지 않는다 — 홈 기록이 이미 "응답이 곧 노출"이다(ADR-043)
- **귀속은 노출된 상품으로 한정한다.** 사용자 단위 전체 행동(노출과 무관한 구매까지)을 세면 추천과 상관없는 변동이 섞인다. 창은 클릭 30분, 구매 24시간
- **분석은 SRM 을 먼저 본다.** 비율이 어긋나면 배정이나 기록이 새고 있는 것이라 차이를 읽지 않는다
- **실험군의 설정은 코드에 고정한다**(구매 이력 + 재구매 우선). 변형의 뜻이 설정마다 달라지면 결과를 못 읽는다

## 버린 것

| 안 | 이유 |
|---|---|
| 배정 표(사용자 → 변형) | 해시로 같은 성질을 얻는다. 표는 쓰기와 갈라짐을 더한다 |
| 노출 이벤트를 따로 발행(Kafka) | ADR-043 과 같은 이유 — 관측을 아웃박스에 태우지 않는다 |
| 사용자 단위 전체 전환 | 추천과 무관한 구매가 섞인다. 필요하면 분석 스크립트에 지표로 더할 수 있다(기록은 이미 있다) |

## 대가 (정직하게)

- 검증은 합성 행동이다. 기반이 맞게 돈다는 것만 말한다
- 변형당 500명에서 구매 3%p 차이는 구간 폭(±2.8%p)과 비슷하다. 실사용자 실험의 표본 크기를 이 폭으로 정해야 한다
- 2쪽부터의 노출에는 변형을 적지 않는다. 추천 행이 1쪽에만 있어서다

## 다시 볼 조건

- 실사용자 트래픽이 붙으면 → `rec-history` 를 켜고 같은 분석으로 판정한다. 귀속 창은 그 데이터로 다시 정한다
- 변형이 홈 다음 쪽까지 바꾸게 되면 → 2쪽 노출에도 변형을 적는다
