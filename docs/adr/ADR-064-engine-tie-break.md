# ADR-064. ES·OpenSearch 도 동점을 상품 id 로 끊는다: 두 엔진의 차이는 전부 동점 순서였다

- 상태: **채택**
- 날짜: 2026-09-24
- 관련: `EngineQuery`, `EngineIndexer`, `tools/search/products-index.json`, [실측 리포트](../performance/es-os-ranking-diff.md),
  [ADR-051](ADR-051-search-engine-by-quality.md), 이슈 #262

## 맥락

ADR-051 은 ES 와 OpenSearch 의 상위 10개 겹침이 0.753 이라고 적고 원인을 남겨 두었다. #258 에서 Lucene 은 동점을 내부 문서 번호로 줄 세워
색인이 바뀌면 순서가 흔들린다는 것을 확인했고, ES 쪽은 재지 않았다.

## 판정 기준 (이슈 #262 에 측정 전에 적었다)

- 다른 쿼리의 과반이 "동점만 다름"이면 ES·OpenSearch 에도 동점 정렬을 넣고 겹침을 다시 잰다. 0.95 이상이면 채택
- "점수가 다름"이 과반이면 원인 항을 적고 질의는 바꾸지 않는다

## 결과 (대입)

#236 절차로 색인했을 때 다른 쿼리 197개 전부가 동점 순서였다(점수가 다른 쿼리 0). 일부러 순서가 갈리게 색인한 두 엔진에서 동점 정렬 전 0.912,
뒤 **1.000**. 채택.

## 결정

- ES·OpenSearch 검색·필터 본문을 **점수 내림차순, 상품 id 오름차순**으로 정렬한다
- 색인 문서에 `product_id`(long) 를 넣는다. 적재 스크립트와 CDC 색인기가 같이 넣는다
- ADR-051 의 "원인은 확인하지 못했다"를 닫는다: 엔진 차이가 아니라 색인 절차가 만든 문서 순서 차이였다

## 대가 (정직하게)

- **이미 만든 ES·OpenSearch 색인은 다시 만들어야 한다.** `product_id` 가 없는 문서에서는 두 번째 정렬 키가 비어 동점이 그대로다
- `flip flop` 한 쿼리는 점수 자체가 색인을 만들 때마다 달랐다(같은 엔진 안에서도). 원인은 확인하지 못했다. 동점 정렬 뒤 상위 10개에는 영향이 없었다
- 정렬에 `_score` 를 명시하므로 두 번째 키 없이 점수만 쓰던 때보다 요청이 조금 무겁다. 재지 않았다(Lucene 쪽은 #258 에서 차이 없음)

## 다시 볼 조건

- 두 엔진의 결과가 다시 갈리면 → `engine_diff.py` 로 같은 분류를 돌린다. "점수 다름"이 늘었으면 그때는 엔진 버전 차이를 본다
