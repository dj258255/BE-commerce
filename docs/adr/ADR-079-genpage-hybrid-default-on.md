# ADR-079. 홈 2쪽 줄 구성 기본값을 결합 방식(HYBRID)으로 켠다

- 상태: 채택 (Accepted)
- 날짜: 2026-10-05
- 관련: [ADR-068](ADR-068-genpage-v2-not-default.md) · [ADR-067](ADR-067-genpage-page-shares-capacity.md) · [ADR-060](ADR-060-genpage-serves-purchases.md) · [백엔드 실험](../../personalization/docs/genpage-v2/BACKEND.md) · 이슈 #467

## 맥락

ADR-068 은 v2 를 추천 모델 기본으로 삼지 않기로 하고 다시 볼 조건 넷을 남겼다. 그중 서빙 경로 조건과 가상 사용자 A/B 조건을 D5 다음의 S1 · S2 · S3 · S4 로 하나씩 채웠다. S4 는 실제 앱 홈 2쪽과 같은 3행 × 8개 구성에서 규칙 줄 구성과 결합 방식을 짝으로 겨뤄 결합 방식이 이겼다. 남은 것은 기본값을 켜는 결정이다.

## 결정

홈 2쪽 GenPage 요청의 줄 구성 기본값 `app.recommendation.genpage-compose` 를 `OFF` 에서 `HYBRID` 로 바꾼다. ADR-068 의 결정(v2 를 추천 모델 기본으로 삼지 않는다)은 그대로 두고 홈 2쪽 줄 구성만 켠다.

되돌리는 방법은 환경변수 `APP_RECOMMENDATION_GENPAGE_COMPOSE=OFF` 한 줄이다.

## 근거

- D5 (오프라인, 2026-10-01): 순위 모델 점수 위에서 GenPage 가 줄을 구성하는 H'(4) 가 규칙 줄 구성을 페이지 nDCG 로 이겼다. +2.0%, 짝 부트스트랩 [+0.0009, +0.0013]
- S1 (서빙, 2026-10-04): 결합 방식을 모델 서버 `/page` 에 붙였다. 홀드아웃 500명 전원이 오프라인 D5 페이지와 같았고 서버 추론 p95 142 ms 로 예산 안이었다
- S2 (앱, 2026-10-04): 결합 방식을 앱 홈 2쪽 기능 플래그로 붙였다. 매핑 계정 200개가 서버 응답과 같았고 앱 기본 설정에서 HYBRID 2쪽 p95 119 ms 로 지금 방식(125 ms)보다 빨랐다. 매핑 없음 · 점수 없음 · 모델 정지 세 경우 모두 오류 0 이었다
- S3 (가상 A/B, 2026-10-04): 6행 페이지 짝 설계에서 실제 구매 적중이 +0.0044 [+0.0030, +0.0058] 로 결합 방식이 이겼다
- S4 (앱 구성 짝, 2026-10-05): 3행 × 8개 페이지 짝 설계에서 주 지표(3개 미만 행 제거 후 실제 구매 적중)가 +0.0049 [+0.0039, +0.0059] 로 이겼다. 실패 0 · 대체 0

## 전제 조건

기본값을 켜도 조건이 갖춰지지 않은 환경은 지금과 같다.

- 결합 방식은 모델 서버가 `--scores` 로 떠 있을 때 동작한다. 매핑 고객의 이력은 `--history-store` 로 읽는다
- 매핑이 없으면 `compose` 를 보내지 않는다. 점수가 없으면 서버가 `generate` 로 대체한다. 서버가 없거나 실패하면 규칙 행으로 물러선다
- 그래서 모델 서버가 붙지 않은 환경에서는 기본값이 켜져 있어도 요청 · 응답 · 지표가 지금과 같다

## 한계

- 효과(결합 방식이 이겼다)의 근거는 오프라인 평가와 가상 사용자 짝 A/B 다. 지연 · 서빙 일치 · 대체 경로는 실제 서빙(S1) · 앱 경로(S2)에서 쟀다. 실제 사용자 A/B 는 없다
- S4 의 비교가 재는 것은 홈 2쪽 구성뿐이다. 1쪽(추천 행 · 규칙 행)은 두 팔이 같아 짝 차이에 영향이 없다

## 다시 볼 조건

- 실제 사용자 A/B 에서 주 지표가 반대 방향이면 기본값을 다시 본다
- 모델 서버가 붙지 않은 환경에서 기본값이 부하나 지연 문제를 만들면 다시 본다
