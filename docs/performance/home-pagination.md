# 홈 페이지네이션 실측: 커서가 중복을 막고, 세션 활동이 다음 쪽을 바꾸는가 (#237)

판정 기준은 [이슈 #237](https://github.com/dj258255/BE-commerce/issues/237)에 측정 전에 적었다. 결정은
[ADR-052](../adr/ADR-052-home-pagination-cursor.md).

## 무엇을 쟀나

사용자 30명(합성 계정)마다 다음 순서로 실제 API 를 불렀다(`tools/home_pagination_eval.py`).

1. 가입·로그인 → 1쪽(활동 없음)
2. 커서로 2쪽을 한 번 받아 **세션이 없을 때의 첫 행**을 확인하고, 그 대분류가 아닌 대분류의 상품 하나를 본다
3. 기다린 뒤(0ms 또는 50ms) 같은 커서로 2쪽을 받는다 → **첫 행이 방금 본 대분류인가**
4. 같은 2쪽을 "보여 준 상품을 비운 커서"로도 받아 1쪽과 겹치는 상품 수를 센다(커서가 상품을 안 들고 다녔다면)
5. `nextCursor` 가 없어질 때까지 넘기며 쪽 수·지연·커서 길이를 적는다

## 1차: 기준을 못 넘었고, 원인이 둘이었다

| 조건 | 세션 반영 | 커서 있을 때 중복 | 커서 없을 때 중복(2쪽 평균) |
|---|---:|---:|---:|
| IN_REQUEST | 60% | 0 | 9.3 |
| KAFKA · 대기 0ms | 0% | 0 | 9.6 |
| KAFKA · 대기 50ms | 0% | 0 | 9.7 |

- **KAFKA 0% 는 실험 설정의 실수였다.** KAFKA 전달은 `kafka` 프로파일이 있어야 발행·소비가 돈다(설정 주석에 적혀 있다).
  프로파일 없이 띄웠으니 컨텍스트가 아예 갱신되지 않았다. 게다가 **나가는 기본값은 IN_PROCESS** 다. 조건을 바꿨다
- **IN_REQUEST 60% 의 놓친 12건** 가운데 6건은 평가 스크립트가 대분류가 NULL 인 묶음을 대상으로 고른 것이었다(스크립트 결함)
- **나머지 6건(아동복)은 설계 결함이었다.** 인기 표에 아동복이 **0개**다(여성복 266 · Divided 106 · 스포츠 16 · 남성복 12).
  사용자가 아동복을 봐도 그 행을 만들 재료가 없어 **세션 신호가 조용히 버려졌다**

처방: 인기 후보가 모자란 대분류는 **그 대분류의 신상품으로 채운다**(항목 `reason` 이 "대분류 신상품"이라 인기와 구분된다).

## 2차 (처방 후)

| 조건 | 세션 반영 | 커서 있을 때 중복 | 커서 없을 때 중복 | 쪽 수 | 1쪽 p95 | 다음 쪽 p95 |
|---|---:|---:|---:|---:|---:|---:|
| **IN_PROCESS · 대기 0ms**(기본값) | **96.7%** | 0 | 8.6 | 3 | 96ms | 81ms |
| IN_PROCESS · 대기 50ms | **100%** | 0 | 8.7 | 3 | 98ms | 86ms |
| IN_REQUEST | 100% | 0 | 8.6 | 3 | 101ms | 85ms |

- **기준 2(세션 반영 90% 이상) 충족.** 대기 0ms 에서 놓친 1건은 비동기 반영이 요청보다 늦은 경우다 — 50ms 를 기다리면 없다(E1 의 무릎과 같다)
- **기준 1(커서 있을 때 중복 0) 충족.** 커서가 상품을 안 들고 다니면 2쪽에서 평균 8.6개가 다시 나온다
- **대가**: 신상품으로 채우는 조회가 더해져 다음 쪽 p95 가 54ms → 81~86ms 다
- **커서 길이**: 2쪽 커서 120자, 3쪽 커서 395자(상품 하나에 약 10자). 상한 4,096자 안에서 ~~약 10쪽~~ **16쪽**까지 들어간다(#348 에서 실제 커서로 이어 붙여 쟀다: 16쪽 뒤 4,231자. 상한을 올려도 톰캣 요청 헤더 한도가 약 7,850자 · 30쪽에서 먼저 막는다)

## 재현

```bash
docker compose up -d mysql redis
./gradlew -p commerce bootJar
USERS=30 bash tools/run-home-pagination.sh
```

## 이 측정이 말하지 않는 것

- 대분류가 5개라 쪽 수가 3쪽에서 끝난다. 중분류 행을 넣으면 쪽이 늘고 커서도 길어진다
- 합성 계정이고 활동 하나만 심었다. 실제 세션은 여러 대분류를 섞어 본다
- 쪽을 넘기는 동안 카탈로그·인기 표가 바뀌는 경우는 재지 않았다
  - 쟀다([#258](search-paging-churn.md)): 인기 순위를 섞고 상위 상품을 품절시켜도 쪽 사이 중복 0 · 품절 노출 0
