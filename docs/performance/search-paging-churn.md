# 쪽을 넘기는 사이 색인이 바뀔 때: 검색은 흔들렸고, 홈은 흔들리지 않았다 (#258)

검색 결과 상품의 가격이 바뀌는 동안 쪽을 넘기면, 1~3쪽 스냅숏 3,000개 중 888개(30%)가 끝내 안 나오고 88개가 두 번 나왔다. 가격은 검색어와
무관한데도 그랬다. 동점을 상품 id 로 끊자 중복 0, 누락 9 가 됐다. 판정 기준(0)은 엄밀히 넘지 못했고, 남은 9건은 동점 정렬로 풀 수 없는 원인이다.
홈은 인기 표와 재고가 바뀌어도 중복·품절 노출이 0 이었다. 기준은 [이슈 #258](https://github.com/dj258255/BE-commerce/issues/258)에 **측정 전에** 적었다.
결정은 [ADR-062](../adr/ADR-062-search-tie-break-by-id.md).

[홈 페이지네이션 리포트](home-pagination.md)의 "말하지 않는 것"에 "쪽을 넘기는 동안 카탈로그·인기 표가 바뀌는 경우는 재지 않았다"가 있었다.
#246 으로 검색 색인이 1초 안에 바뀌게 되면서 같은 질문이 검색에도 생겼다. 검색은 오프셋(`page`) 방식이다.

## 예측 (측정 전)

이름이 같은 상품이 많아 검색 점수가 같은 동점이 많다. Lucene 은 동점을 내부 문서 번호로 줄 세우고, 문서를 갈아 끼우면(NRT) 번호가 바뀐다.
그래서 검색어와 무관한 변경(가격)만으로도 동점 무리의 순서가 바뀌어 쪽 사이에 중복·누락이 생길 것이다.

## 방법 (검색)

- Lucene + CDC(기본 엔진, ADR-056). 결과가 3쪽(20개씩) 이상인 쿼리 50개(#236 의 A 묶음, seed 7)
- 쿼리마다 스냅숏(1~3쪽을 연달아) → 1쪽 → 3초 변경 → 2쪽 → 3초 변경 → 3쪽. 변경은 초당 20건
- 중복 = 앞 쪽에 나온 상품이 뒤 쪽에 다시 나온 수. 누락 = 스냅숏 1~3쪽에 있었는데 끝내 안 나온 수
- 변경 방식: 없음 · 카탈로그 무작위 상품의 가격 · **그 쿼리 결과 상품(스냅숏 상위 120개)의 가격**(측정 전에 이슈에 덧붙인 조건) · 새 상품 추가(이름이 검색어와 같다)

## 결과 (검색)

| 변경 | 동점 = 내부 문서 번호(지금까지) | | 동점 = 상품 id | |
|---|---:|---:|---:|---:|
| | 중복 | 누락 | 중복 | 누락 |
| 없음 | 0 | 0 | 0 | 0 |
| 카탈로그 무작위 가격 | 0 | 0 | 0 | 0 |
| **결과 상품의 가격** | **88** | **888**(50/50 쿼리) | **0** | **9**(4/50 쿼리) |
| 새 상품 추가 | 68 | 2,000 | 42 | 2,000 |

- **예측이 맞았다.** 검색어와 무관한 가격 변경이 결과 상품에 몰리면 모든 쿼리가 흔들렸다
- **무작위 변경으로만 쟀다면 "문제 없음"이라고 적었을 것이다.** 10만 건 중 무작위로 고른 변경은 쿼리 하나의 결과에 거의 걸리지 않는다.
  그래서 측정 전에 B2(결과 상품에 몰기)를 덧붙였다
- **판정 기준(가격 변경 아래 중복·누락 0)은 엄밀히 못 넘었다.** 남은 누락 9건은 모두 여러 단어이거나 오타 허용이 걸리는 쿼리였다
  (`pyjama set` 3 · `outdoor waistcoat` 4 · `hair` 1 · `underwear bottom` 1)
- **새 상품 추가는 동점 정렬로 막을 수 없다.** 이름이 검색어와 같은 새 상품이 위로 끼어들어 뒤 두 쪽(쿼리당 40개)이 통째로 밀렸다.
  막으려면 오프셋이 아니라 커서(마지막 점수·id 다음부터) 방식이어야 하고, 그래도 위로 끼어든 상품은 안 보인다

### 남은 9건의 원인

Lucene 은 문서를 갈아 끼울 때 옛 판을 지웠다고 표시만 하고, 병합 전까지 그 판도 단어 통계(문서 빈도)에 남긴다. 가격만 바꿔도 그 상품의
단어들의 IDF 가 조금씩 내려가고, **다른 단어로 점수를 얻는 상품과의 순서**가 뒤집힐 수 있다. 같은 이름끼리의 동점은 id 정렬이 지키지만,
여러 단어 쿼리에서 단어마다 다른 상품이 맞는 경우는 점수 자체가 움직인다. 이 성질을 단위 테스트(`LuceneTieOrderTest` 의 두 번째)로 고정했다:
`alpha` 쪽 문서 세 개의 가격만 바꿨더니 `alpha` 상품이 `beta` 상품 아래로 내려갔다.

### 비용

같은 벤치마크(10.6만 건, `LuceneScaleBenchmark`)를 main 과 동점 정렬 jar 로 두 번씩: 동시성 10 p95 19.7 · 26.2ms 대 18.6 · 20.4ms.
흔들림 범위 안이다.

## 홈 (A)

사용자 30명마다 1쪽 → (인기 표 `recent_7d` 순위를 무작위로 섞고 인기 상위 상품 10개를 품절) → 2·3쪽.

| 쪽 사이 중복 | 품절 노출(2·3쪽) | 쪽 수(중앙값) |
|---:|---:|---:|
| 0 | 0 | 3 |

홈은 커서가 보여 준 상품을 들고 다니고(ADR-052), 품절은 요청마다 거른다. 인기 표가 바뀌어도 그 두 성질이 유지됐다. 그대로 둔다.

## 한계

- 변경은 가격 하나였다. 재고(필터 `inStock`)가 바뀌면 결과 집합 자체가 바뀌어 누락이 정의상 생긴다
- ES·OpenSearch 도 동점을 내부 순서로 둔다. 이 이슈는 Lucene 만 바꿨고 ES 쪽은 재지 않았다. 나중에 같은 정렬을 넣었다(#262, [ADR-064](../adr/ADR-064-engine-tie-break.md))
- 쪽 사이 3초, 이 머신 한 대
